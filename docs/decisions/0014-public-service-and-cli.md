# Decision 0014: Public service, CLI transport and the operator guard

Status: accepted (Task 12a) · Date: 2026-10-19 · Host observed: Claude Code 2.1.301 fixtures (capture); installed CLI 2.1.303; no live route (B1)

## Context

Task 12a builds the public service and the `recalith` CLI (SYSTEM_SPEC §5.1.1, §6.1, §7.1.2, §7.3, §13, §13.1, §14; DATA_CONTRACTS §1.1, §11, §12; ACCEPTANCE_TESTS A19, A32, A33, A53, A60, A72, A73) on the Task 5 application path, the Task 9 review path and the Task 10 hold/recheck paths. The documents fix the rules: the guard inspects the original caller before any actor is assigned; markers refuse even with a terminal and a token; no marker clearing, synthesized terminal, bypass switch or reuse of the worker/curator environment builder; token create/revoke need the unmarked terminal; pre-init tokens bootstrap a noninteractive first init and never overwrite a store; refusals are exit 6 with a content-free audit when a store exists and nothing created otherwise; declarations are never admitted without their review; a correction invalidates at once and queues the replacement's review without a model call; JSON stdout is exactly one object; exit codes 6/7/8. They leave open where an installation keeps its token verifiers, what counts as an interactive terminal on each OS, which proposition key a typed declaration gets, what event a typed declaration or correction records, how a retried command avoids a second effect, what the `observe`/`context` stdin carries, how the refusal audit is written, what a correction's replacement looks like for each claim kind, and what `status`/`doctor` may claim before Task 17. Task 12a needed one answer for each. Nothing here weakens a rule; where a rule was ambiguous the stricter reading was taken.

## Decisions

1. **Layers.** `recalith.service` is the public service: every function takes a resolved `InstallationContext` and returns a strict DTO or a JSON-ready mapping; it never prints, reads a terminal, inspects markers or imports a host entry point (`fast.entry`, `fast.claude_capture`). `recalith.cli` (`main` parsing/output/exit codes, `operator_guard`, `inspect` read-only forms, `mutate` administrative forms) is the only transport in this build; `recalith.__main__` hands over to `cli.main.main`. No domain module imports the CLI (fresh-process and static audits, `tests/platform/test_hook_imports.py`). Business policy stays in the domain: the CLI parses, guards, dispatches and renders.
2. **Guard order** (`cli/operator_guard.py`, before any actor): (a) argument syntax (exit 2); (b) any registered host marker (`CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`) or engine role marker (`RECALITH_WORKER_INSTALLATION`, `RECALITH_CURATOR_INSTALLATION`) present with any value — Windows names case-insensitively — refuses (`host_marker|worker_marker|curator_marker`); (c) a supplied `--operator-token-file` must be a regular file (no link; `lstat` and `fstat` agree), at most 4 KiB, owned by the effective user with no group/other bits (POSIX), and a strict `OperatorTokenFile`; any failure refuses (`token_refused`, reason `token_unreadable|token_not_regular_file|token_oversized|token_owner_mismatch|token_permissions_too_open|token_malformed`), never 2 and never a terminal fallback; (d) token create/revoke need the terminal (`terminal_required`; a token never substitutes); every other form needs the terminal or a token (`terminal_or_token_required`, category `unmarked_noninteractive`); (e) for an existing installation a supplied token must match an active, unrevoked verifier (`token_revoked|token_not_recognized`). Only then is `Actor(kind="operator", id=<token ID or "terminal">, channel="cli")` assigned. The original caller's environment is a snapshot of the process environment, never modified; `spawn_environment` is called only to build a worker child's environment after the guard passed (`worker start|run`).
3. **Interactive terminal.** POSIX: standard input is a terminal *and* the process has a controlling terminal (`/dev/tty` opens). A terminal descriptor alone (a detached or agent-launched process holding one) is noninteractive. Windows: standard input is a console input handle (`GetConsoleMode` succeeds); `isatty` is not used because it is true for `NUL`. Tests drive these through a real pseudo-terminal made the controlling terminal of a new session (POSIX) and a real new console (`CREATE_NEW_CONSOLE`, `CONIN$` on standard input; Windows); these are controlled test states, not evidence of a live IDE workflow.
4. **Token verifiers live in `local.toml`** (SYSTEM_SPEC §13.1: "init installs its verifier in the new `local.toml`"), in tables `operator_verifiers` (token ID → `v1:<salt hex>:<SHA-256 of a domain tag, the token ID, the salt and the secret>`) and `operator_revoked` (token ID → time). The secret is never stored. Init writes the verifier in the same `local.toml` write that completes the installation — also when it completes an interrupted init, so a crash between the store rename and `local.toml` cannot leave a token-provisioned installation without its verifier (failpoint `init.after_store`; the matrix catches the defect, single-process tests do not). A later `operator-token create` at the terminal registers its verifier when `--project` names an existing installation; otherwise it creates a standalone file and performs no installation lookup. Revocation is permanent per installation; a revoked ID is never registered again. No schema migration is needed (no `0008.sql`).
5. **Typed declarations** (`service.declare`, `submit_declaration`): operator actor only; kind `decision|preference`; the exact statement (≤ 4,096 characters, no surrogate or NUL, and refused — not silently scrubbed — when it holds a credential-shaped value). One transaction records an `operator_declaration` event (user channel, `explicit_user`, its own root; payload `statement`, `declaration_kind`, `scope`) through the ordinary ingestion helper (`capture.pipeline.ingest_in_transaction`: root class, revision hooks, `ingest` job), then applies one `propose_claim` (`basis` `user_declared`, support = the whole `statement` span) through `controller.apply.apply_in_transaction` (kind `apply_service`). Admission and review are unchanged: the claim is a weak candidate, its review job is scheduled at the declaration band with origin `typed_declaration`, and only a supported review admits it; an exhausted budget leaves the review `waiting_budget`. **Proposition key:** code-derived, `{subject: "declaration " + the first 24 hex of SHA-256(statement), predicate: kind}`, since the contract form carries no subject; consequently typed declarations are grouped with others only when their text is identical (an intent question between two differently worded typed declarations is not raised automatically — a known gap).
6. **Corrections** (`service.correct`, `submit_correction`): operator actor only; the target's head must equal `--expected-revision` (`revision_conflict`, exit 3, nothing applied). One transaction records an `operator_correction` event (payload `statement`, `target`), invalidates the target (`change_claim_status` citing the statement as `contradicts`; the guidance epoch advances, so the next packet excludes it, whatever the budget) and proposes the replacement, which depends on the invalidation (one atomic group). The replacement follows the target's type and evidence policy: a decision/preference becomes a `user_declared` claim of the same kind; anything else an `inferred` claim of the same kind (never `observed`); a failure lesson or procedure keeps the target's body, its event support and its non-claim dependencies (fingerprints re-resolved by code) plus the statement; scope, conditions and proposition key are the target's. Its review is scheduled with origin `operator_correction` (`apply_in_transaction(..., review_origin=)`); held supersessions of the target become stale through the Task 10 path. Any refused decision rolls back the whole submission, event included.
7. **Retries have one effect.** A submission's event identity derives from its content (`[kind, statement, scope]`; `[claim ID, expected revision, statement]`) and its application from the event (`op_` over the event ID), so an operator re-running the same command after a crash or a lost reply gets the original result with `duplicate: true` (checked before the revision check); nothing is applied twice. Re-declaring identical text after its earlier candidate was rejected therefore returns that earlier result; a reworded statement is a new declaration.
8. **Audit.** A refusal spools one `agent_attempted_operator_command` event (memory channel, derived, no root) with exactly `command_kind`, `marker_category` (`host_marker`, `worker_marker`, `curator_marker`, `unmarked_noninteractive`, `token_refused`) and `reason_code` `policy_refused` — through the ordinary capture spool, never SQLite — when `local.toml` exists. A failed audit (spool unwritable, disk full, unreadable store) still refuses with `audit: unavailable`; before an installation exists the refusal reports `audit: no_installation` and creates nothing.
9. **Output.** Success: `{ok: true, command, result}`; partial capability (exit 8): additionally `status: capability_degraded` and `degraded: [reason codes]`; failure: `{ok: false, command, error, message, exit_code, …}` (a refusal adds `refusal: {reason, category, audit}`). With `--json` stdout is exactly that one object on one line; otherwise it is indented; diagnostics go to stderr as `recalith: <code>: <message>` without statements, tokens or arguments. An unexpected exception is `storage_failure` (5) naming only its type.
10. **Stdin forms.** `observe --stdin` takes one observation `{source_event_key, text, host_session_id?, occurred_at?}` or `{observations: [...]}` (1–64); each becomes a `generic_observation` on the external channel with `untrusted` authority (adapter `recalith_cli`), captured through the spool: exit 0 with the accepted event IDs, 7 when durability was not acknowledged. `context --stdin` takes `{text?, action?, environment?, max_estimated_tokens?, branch_ref?}`; flags give purpose, session and task; the packet is `retrieval.compile.compile_context`'s (purpose `manual` budgeted at 2,000), exit 8 when it carries degradation reasons.
11. **Inspection.** `status` and `doctor` are content-free and always exit 8 in this build (`health_composition_unavailable`): they report worker, queue, capture and route state, `health.state = unavailable` (Task 17), `autonomous_ready: false` and `readiness: not_evaluated`; `doctor` adds `PRAGMA quick_check` and `revision_chain: unavailable_in_preview`. `search` is `retrieve` for current guidance plus, with `--history`, retired claims whose proposition contains every query word (bounded scan of 2,000 heads); lists are cursor-paginated (default 50, maximum 200). Read-only forms use a `host_agent` reader with no memory authority.
12. **Forms owned by later tasks** pass the same guard and then answer `capability_unavailable` (4) naming their owner: `integrate` and `--remove` (13), `backup` (15), `restore` (15/16), `forget --apply` and `--preview` (16), `export`/`import`/`import breadcrumbs`/`upgrade`/`project fork`/`workspace attach`/session worker mode/`doctor --full-integrity` (full release), `doctor --probe-host|--probe-provider` (13/17); `init --release-profile full` is unavailable in this preview engine. `jobs retry` (a `failed` job only) and `worker start|stop|run --mode persistent`, `workspace rebind|discard-copy`, `undo --apply` are implemented.
13. **Failpoints.** `service.after_event`, `service.after_commit` and `init.after_store` join `service.before_commit` in `failpoints.SERVICE` (armed only programmatically).

## Consequences

Wired now: the service and the CLI transport for every DATA_CONTRACTS §12 form, the guard, pre-init tokens and verifiers, guarded `declare`/`correct` on the unchanged review/hold/recheck paths, `undo`, `jobs retry`, worker control, rebind/discard, `observe`, `context`, `search`, `show`, lists, `status`/`doctor` without readiness claims. Consumer-side hooks for later tasks: Task 12b adds the delivery branch of `handle_hook`, `record_delivery`/`hook_record_delivery`, receipts, suppression, per-session question deduplication, the session overlay, `branch_ref`/environment/`substitute_pre_action` supply and in-flight emission bounds; Task 13 installs host command-pattern deny rules for the administrative forms, certifies marker inheritance on the real host and runs the live operator workflow; Tasks 15/16 implement backup/restore/forget behind the existing guarded forms; Task 17 composes health, so `status` stops reporting `health_composition_unavailable`; an MCP transport (full release) reuses `recalith.service` without `declare`/`correct`. A live operator workflow from a real IDE host has not been run (B1 and Task 13); the simulated callers prove the guard's decisions only.
