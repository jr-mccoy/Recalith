# Decision 0006: Project worker, registered start and budget ledger

Status: accepted (Task 4 preview slice) · Date: 2026-10-16

## Context

Task 4 builds the persistent worker (SYSTEM_SPEC §4, §6.1–6.3), the stdlib role-environment helper (DATA_CONTRACTS §2.3) and the job/budget rules (DATA_CONTRACTS §8). The documents fix the policy but leave open how the hook learns that it may start a worker, how the hook and worker agree on "one worker per installation", what the hook does when it is short of time, where a reservation lives, and how a waiting reason is shown. Task 4 needed one answer for each. Nothing here weakens a rule; where a rule was ambiguous the stricter reading was taken.

## Decisions

1. **Consent to start lives in the hook-context manifest.** `context_schema` 2 adds `worker = {autostart: bool, route_keys: [names]}` to `.recalith/run/hook-context.json`. `autostart` is the integration's consent for the hook to start this installation's worker; Task 13's `integrate` writes it `true`, and `capture.hooks.write_hook_context` keeps it `false` unless asked, so tests and tools never start workers by accident. `route_keys` names the exact environment keys of the explicitly selected provider route that the worker may carry for its curator child (empty until Task 7 configures a route); a marker or `RECALITH_*` name is invalid. A schema-1 manifest still captures, with autostart off: an old manifest never costs capture.
2. **Registered start path.** `recalith.fast.process_env.ensure_worker` runs in `handle_hook` after capture has finished (acknowledged or not) and before the optional overlay. It probes the installation lock, skips a start attempted in the last 10 seconds (`run/worker-start.json`), builds the worker environment with `spawn_environment(purpose="worker")` from the hook's own environment, and starts exactly `<the hook's pinned interpreter> -I -m recalith.controller.worker --project ROOT --spawned-by hook --spawn-method M`. It never calls the `recalith` CLI (A73 permitted-start control) and never waits for the worker. `subprocess` is imported only on this path, so capture-only hooks keep their import inventory. The reply carries `worker` (`worker_started`, `worker_running`, `worker_start_pending`, `worker_autostart_disabled`, or a degradation below).
3. **Deadline.** The start needs at least 30 ms of the shared 250 ms soft deadline (twice, before and after the lock probe); otherwise it is shed with `deadline_worker_start_skipped` and the next hook tries again. Capture is never what gets shed. In preview, which has no wake hint, the worker start sits at the wake hint's place in SYSTEM_SPEC §5.1.1's order: after capture, before the overlay. Other degradations are `worker_start_failed`, `worker_start_unavailable` (no interpreter path or lock primitive) and `worker_independence_degraded`.
4. **Detachment.** POSIX: a new session (`setsid`) with standard handles on the null device and `close_fds`. Windows: `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_BREAKAWAY_FROM_JOB` with a handle list restricted to the null-device standard handles. If the host's Job Object forbids breakaway (access denied), the start is retried without breakaway and reported `worker_independence_degraded` (`job_breakaway_denied`): the worker then lives only as long as that job, and status says so. Survival is tested natively by terminating a simulated host's process group (POSIX) or kill-on-close Job Object (Windows) and checking continued ingestion; a cgroup- or systemd-scope kill on Linux is outside what a new session escapes and remains for Task 13's real-host termination test.
5. **Internal entry refusal.** `python -m recalith.controller.worker` is not the guarded public `recalith worker` CLI and grants no operator actor. It refuses (exit 6) a caller that still carries a host marker or a curator marker, or whose `RECALITH_WORKER_INSTALLATION` does not name the resolved installation. Only an environment built by `spawn_environment` passes. This is same-user friction, like every guard in SYSTEM_SPEC §13.1.
6. **Environment manifest.** `spawn_environment(manifest, inherited, *, purpose)` takes `{manifest_schema: 1, purpose, installation_id, platform_keys, route_keys, overrides}`. Platform keys come from a per-OS registry (POSIX `PATH`, `LANG`, `LC_ALL`, `LC_CTYPE`, `LC_MESSAGES`, `TZ`, `TMPDIR`; Windows `SYSTEMROOT`, `WINDIR`, `SYSTEMDRIVE`, `PATH`, `PATHEXT`, `TEMP`, `TMP`, `NUMBER_OF_PROCESSORS`, `PROCESSOR_ARCHITECTURE`); home and configuration directories are not inherited. A platform value that looks like a credential is dropped. Overrides are nonsecret and may not name a marker. Markers and every `RECALITH_*` name are removed after selection, then the one role marker is set. Windows names match case-insensitively. Diagnostics report names only.
7. **One worker per installation.** `.recalith/run/worker.lock` is held for the worker's lifetime with `flock` (POSIX; per open file description, so it also excludes a second worker in the same process) or `msvcrt.locking` on byte 0 (Windows). The OS releases it when the holder dies. A starting worker retries for 1 second, so the hook's momentary probe never makes it give up; a second worker then exits 0 without touching the queue. At start, holding the lock, the worker returns every lease of a dead worker to `pending` (generations kept, so their results stay fenced) and charges every unsettled reservation in full (unknown usage).
8. **Leases and fencing.** Every write for a leased attempt goes through `jobs.fenced`, which requires the same owner, the same `lease_generation`, state `leased` and an unexpired lease. Deterministic leases last 60 s; model leases last the model timeout plus 60 s. The proposal is persisted under the fence before application; application plus completion is one fenced transaction. A failpoint family (`job.after_lease`, `job.after_reserve`, `job.after_proposal`, `job.before_complete_commit`, `job.after_complete`) joins the capture family; `failpoints.CAPTURE` and `failpoints.WORKER` name the two matrices.
9. **Scheduling bands.** `Job.priority` holds a code-assigned band: model work 1 correction/declaration review, 2 ordinary review, 3 episode, 4 extraction and task narrative, 5 revalidation (SYSTEM_SPEC §6.2); deterministic kinds keep their own order (`ingest` first). Ties break on due time, then job ID. `jobs.ReviewCandidate(origin, claim_kind, direct_user_evidence)` carries the guarded facts Task 9 will supply; the review priority is derived from them and a mixed batch takes its highest priority. Review batches are partitioned in order, at most 8 candidates each.
10. **Budget ledger.** `provider_usage` holds one `BudgetReservation` per invocation per UTC day (new ID prefixes `rsv` and `inv`). Protected purposes fill the protected pool first and borrow ordinary capacity per dimension; an invocation is indivisible. A reservation is made in a fenced transaction before launch, after the request is prepared so the input estimate is exact; `lease_next` first checks the purpose's smallest possible reservation, so a job that cannot fit is never leased. Charging: reported usage replaces the estimate; a completed call without reported output is charged its measured body estimate; a timeout, overflow, nonzero exit or invalid envelope keeps the full reservation. Overage is charged to the pool that supplied the invocation, so it pauses further calls visibly.
11. **Visible reasons.** A job that waits keeps its reason in `last_error_code`: `budget_exhausted:<pool>.<dimension>` (`ordinary.` for ordinary purposes, `protected+ordinary.` for protected ones) in state `waiting_budget`, and `provider_unavailable` on pending model jobs when no certified backend is configured (all of preview until Task 7). `jobs.queue_summary` and `budgets.summary` expose counts, reasons, backlog age, per-pool use and per-purpose calls/tokens; the worker writes them into `run/worker.json`, which Task 17 health reads.
12. **Output bounds.** The worker rejects a raw wire over 256 KiB (`wire_stdout_oversized`) and then a decoded body over `3 ×` the purpose allowance (`response_body_oversized`), counted in the body's original UTF-8 bytes after the backend's certified envelope parser unwraps it, before strict parsing (`response_invalid`). Both are charged and retried with the normal backoff. `controller/launch.py` bounds a model child: timeout, stdout cap enforced while reading, stderr retained to 64 KiB, and the whole tree killed (POSIX process group; Windows kill-on-close Job Object assigned while the child is suspended, else reported `tree_bound: degraded`).
13. **Polling and clock jumps.** After a poll with work the next follows in 1 s, otherwise in 5 s; waits are sliced at 250 ms to see a stop request (`run/worker.stop`). A wall-clock jump more than 60 s beyond the monotonic interval is counted. Housekeeping is scheduled for the current 24-hour slot only, and `enqueue(..., coalesce=True)` cancels older unleased jobs of the same kind over the same records (`coalesced`), so a resume produces one job per slot and launches one call per scheduling opportunity.
14. **Expansion.** A response containing `request_evidence` is not persisted; the lane prepares the next round and reserves another invocation, at most `evidence_expansion_rounds` (2) extra rounds; a third request fails the job with `expansion_limit`.

## Consequences

Task 5's `apply_proposal` runs inside `jobs.fenced`; until then the model lane's applier is supplied by tests. Task 6 registers typed task reduction as an ingest reducer. Task 7 supplies the certified backend (its envelope parser is `Backend.unwrap`) and the selected route's keys for the manifest's `route_keys`; the Task 0 probe harness keeps its own builder until it is migrated onto `spawn_environment`. Task 12a adds the guarded `recalith worker start|stop|run` CLI and its A73 refusal branch; Task 13's `integrate` enables autostart and certifies survival against the real host's termination; Task 17 composes `run/worker.json` into health. Session mode, `fast/wake.py`, the IPC wake hint and the 2-second wake target remain full-release work, unavailable in this build.
