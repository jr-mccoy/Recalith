# Decision 0020: Preview evaluation harness, release hardening and the open Task 15 aging item

Status: accepted (Task 18, preview slice) · Date: 2026-10-21 · Host observed: Claude Code CLI 2.1.306 installed (request capture only); scripted payloads in the reviewed 2.1.305 format; no live route (B1)

## Context

Task 18's preview slice is the Cut 1 release gate's harness and evidence: the manifest and replay tests, the 12-scenario comparative smoke against a clean no-memory baseline, three default-budget workload days, the profile-required deterministic/failure/latency gates, the §6.1 demonstrations, the §5.1/§5.2 report and the §8 checklist (IMPLEMENTATION_PLAN Task 18 and "Cut 1 release gate"; ACCEPTANCE_TESTS §2.1, §4–§8). Every live part needs a certified inference route and a live host record, which B1 still withholds. The documents leave open how a harness runs end to end without them, how a working agent is represented in a run that is not live, what "the recorded event timing" of a workload day is when no real day was recorded, how native memory is shown disabled, and how release artifacts are built without signing material. One open Task 15 item (age pruning of derived revision bodies) and one correctness defect the smoke run exposed are resolved here at their owning boundaries. Where a rule was ambiguous the stricter reading was taken; no gate is lowered.

## Decisions

1. **Two run modes, one harness.** `evals/run.py` runs `smoke`, `workload`, `demonstrate`, `report` and `gate` in `live` or `scripted` mode. `live` uses the real Claude Code CLI as the working agent and the installation's certified route as the curator; it refuses (exit 4, with the operator commands) until `preflight` finds a certified route and a `live` host record certifying start and prompt for the installed version, and it never falls back. `scripted` replaces exactly two things — the working agent and the model — and is labeled everywhere as mechanics evidence that never counts toward the gate (`report.counts_toward_gate` is true only for `live`; a scripted report's gate is `blocked`).
2. **The scripted working agent** (`evals/agent.py`) is a fixed policy per smoke scenario: the tool actions a competent agent takes, run for real in the trial workspace (real exit codes and output), with explicit branch points that read only the model-visible context the hooks returned in that session. Its hook payloads follow the reviewed 2.1.305 format and go through the real stdlib hook path in process (`claude_capture.map_hook` with the trial's virtual capture time, then `entry.handle_hook`: capture, compile, fence, reservation, emission, receipts) against a controlled delivery manifest. The clean baseline has no installation and no hooks. The policy measures whether the engine delivered the right thing, not how a live agent uses it.
3. **The recorded curator** (`evals/curator.py`) answers the worker's real model requests at the worker's `Backend` interface with recorded proposals written by the coding agent for these fixtures (smoke: per-scenario claims with evidence matchers, review verdicts, task narratives, revalidation decisions; workload days: generic rules). Event IDs, locators and digests come from the request the real preparers built. It reports no provider usage, so the budget ledger charges the engine's own estimates. Queue, leases, budgets, persisted proposals, admission, review batches, revalidation, projections and delivery are the real engine, driven by a harness-owned `Worker` on the trial's virtual clock (`evals/trial.py: Drainer`, holding the installation lock; the hook's autostart is off in the controlled manifest).
4. **Initialization.** Evaluation installations are initialized by `recalith init --operator-token-file FILE` in a child that inherits the harness's environment unchanged (`--init-route operator_token`); the file is an operator- or CI-provisioned pre-init token, never minted by the harness. From a host-marked process the guard refuses (exit 6) and the trial reports `operator_guard_refused`. The in-process engine initializer the test suites use is allowed only for `scripted` runs (`--init-route test_fixture`, labeled in every trial manifest). The forgetting demonstration's backup/forget/restore run through the service with an operator actor, as the Task 16 suites do, and record that the guarded CLI refused this host-marked process.
5. **No future evidence.** Each trial and arm has its own workspace, home and store. Before every session `trial.evidence_horizon` ingests any pending spool segment (what the worker would do next) and refuses (`future_evidence`) a store holding events of a session that has not run or captured after the session's start; workload days run the same check before every session. Delivery receipts are bookkeeping, never evidence, and are not judged. Scripted runs leave the registered transcript empty: the worker stamps transcript-derived assistant text with its wall clock, which would break the trial's virtual timeline, and no smoke curator uses assistant text.
6. **Native memory is observed, not assumed.** `baselines.observe_native_memory` launches the installed CLI in request capture (loopback endpoint, placeholder key; no account) with a planted `MEMORY.md` sentinel, with and without the disabling configuration (`autoMemoryEnabled: false` in the disposable home's settings and `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`). Only "the control loaded it, the disabled run did not" is `disabled`; anything else labels a live trial `contaminated`, never `no_memory`. Each trial manifest also records inherited instruction files, retrieval services and installation presence; scripted arms record native memory as not applicable (no host session).
7. **Workload days** (`evals/workload.py`) are synthetic, seeded, representative eight-hour timelines (one per project, `evals/workload/days/*.json`, regenerated deterministically by `python evals/workload.py generate` and pinned by a test), with recorded commands, exit codes, outputs and offsets and gold task labels. Replay feeds each event at its recorded time and runs the worker on the same virtual clock between events, under default budgets with the UTC day never reset; nothing is extrapolated from fresh-budget trials and no increased-budget variant is run. Boundary gold is not labeled, so boundary precision/recall is reported as unavailable.
8. **Scoring** is frozen with the smoke gold before comparison (`report.GOLD_TERMS`: a gold lesson is matched by an admitted claim containing every listed term). §5.1 measures carry numerators, denominators and Wilson 95 % intervals; paired outcomes use seeded resampling of whole scenarios; small denominators are reported as inconclusive. Definitions: repeated mistake = a failed command in a later session identical to one that failed in an earlier session of the trial; detour = any other failed command in a later session; legitimate retry = the oracle's `plain_retry_succeeded`; foreground tokens = ceil(bytes/3) of prompts, delivered context and tool output; background tokens = the charged budget estimates; operator interventions = guarded commands the harness needed (always 0 in these runs).
9. **The §7 gate per platform** (`tools/measure_release_latency.py`): fresh `python -I -m recalith.fast.entry` processes, 500 warm (current views; alternating pre-action caution and prompt context) and 500 cold/missing-packet (views deleted) trials against 10,000 corpus heads, usefulness counted only when the expected lesson or fact text was emitted, degraded responses reported separately; separate populations for stale views, 50 first launches in new installations, a busy writer, four concurrent hooks, a 30 ms slow spool fsync and (Windows only) one spool-rename sharing violation, the last two through `tools/fixtures/hook_fault.py`, which arms one failpoint in its own fresh process (failpoints still have no environment or configuration switch). macOS and Windows are measured on their own runners by `.github/workflows/measure.yml`; nothing is extrapolated across platforms. `tools/measure_worker_latency.py` gains macOS (`ps`) and Windows (`GetProcessTimes`, `K32GetProcessMemoryInfo`) process accounting for the 10-minute idle window.
10. **Release hardening.** `tools/build_release.py` builds the wheel and sdist with `uv build`, digests them and the provisioning inputs, checks the wheel holds exactly `src/recalith` plus its metadata, checks the runtime closure of `requirements.lock` with each package's declared license against `docs/release/DEPENDENCIES.json`, and checks for foreign copyright headers (no upstream source is adapted, so no `THIRD_PARTY_NOTICES.md`). `.github/workflows/release.yml` runs it on relevant pushes and by dispatch and uploads the unsigned artifacts; it tags, releases and publishes nothing. Signing needs operator material the repository must not create, and the project's own license is undeclared (an owner decision); both are recorded blockers. `docs/release/claude_preview_checklist.json` itemizes §8 with status, blocker and evidence paths, and `tools/release_checklist.py` verifies the record (every bullet covered, evidence present, the verdict consistent, readiness naming `claude_preview` and the 16 deferred capabilities).
11. **The manifest test** checks the coverage manifest against ACCEPTANCE_TESTS itself (73 IDs, the six exclusions and the §2.1 partial variants parsed from the document) and against IMPLEMENTATION_PLAN's added-case ownership table, and requires every preview variant to name test functions that exist (by AST). It found the manifest lacking owners the plan names (A49/A52/A54 Task 3b, A61 Task 18, A67 Task 4, A73 Task 14), now added.
12. **Derived revision bodies age (Task 15, open since decision 0016).** SYSTEM_SPEC §11's `closed_task_history` (90 days) and `episode_after_closure` (180 days) apply to both profiles (§1.2: only the table or §11 overrides a default), so preview needs them. The sweep finds candidates in its read snapshot, with that snapshot's pin prefilter, and takes the aging write transaction only when one exists; a sweep with nothing to age holds no write lock for it. That transaction recomputes the pin closure and the candidates and ages: every revision body of a completed or abandoned task whose closure is strictly older than 90 days, and every revision body of a settled or archived episode whose task's closure is strictly older than 180 days. Closure is the time of the revision that began the current closed streak (its body's `updated_at`, else its operation's time, so an episode still ages after its task's history is gone). Revisions a live owner or unfinished work cites (the record nodes of the pin closure) are kept. Aging empties the body, removes that revision's evidence links and its projection rows (views republished), keeps the head and its status, writes one content-free `retention_record_aging` operation, advances the guidance epoch, and is reported (`records_aged`). Undo over an aged body is the existing `body_unavailable` conflict; `show` answers a content-free `expired` marker; a late event of an aged task is reduced without reviving it (the reducer treats a body-less closed task as frozen). Failpoint `retention.after_record_aging` joins the retention family.
13. **A changed dependency is never shown as current (Task 11 boundary).** The scripted smoke run's R4 showed a user-declared fact delivered as `current` context after the file it depends on changed outside any captured tool: the bounded live dependency check ran only for failure-lesson cautions. Both compilers now run it for every live claim with registered dependencies and current stored freshness; a value that differs from the recorded fingerprint shows the item `needs_revalidation` with `dependency_false` (SYSTEM_SPEC §8.2 table row 2), and an unknown value leaves the stored freshness. Caution gating is unchanged.
14. **Recorded, not resolved: fresh-session task restoration (L4).** The L4 gold expects a fresh session's start packet to carry the previous task's next step; decision 0013 gives a fresh start with no task binding only open intent questions, and the continuity link needs three path actions (A57). The preview therefore misses L4 by design in both arms. Changing it would alter the continuity and tentative-context rules of SYSTEM_SPEC §3.2/§8.2; it is left as an unmet smoke expectation and an owner question, not changed here.
15. **Recorded, not resolved: prompt usefulness from hook views at corpus scale (§7, Task 11 boundary).** The worker publishes one query-independent view per workspace, task and purpose (`retrieval/compile.py: _view_candidates`): the task's claims, up to 64 action-family claims, 8 disputed claims and the 32 strongest active claims, capped at 48 items for a prompt view. The hook then keeps only lexically relevant candidates. A prompt-specific fact outside that static slice cannot reach the hook, however relevant it is, while the service compiler (full lexical search) delivers it. Measured with one relevant fact among N near-identical corpus heads, the fact is emitted at N = 0 and 50 and absent at N = 200 and 10,000. In the §7 gate every warm and cold prompt trial is therefore degraded, while pre-action cautions (action-family claims, always in the view) are delivered. The healthy eligible delivery targets (≥99 % warm, ≥95 % cold) are unmet for prompt context at reference scale. The concrete fix is a Task 11 design change to the hook's input: a bounded, worker-published lexical lookup into per-claim pre-serialized candidates, read with the stdlib within the same deadline. It changes the view contract (SYSTEM_SPEC §5.1.1 "pre-serializes candidate packets", the DATA_CONTRACTS view bodies) and the A58 budget, so it is not made inside Task 18. Until it lands, the gate result is recorded as failed for this population, and the preview may only be labeled experimental with this target stated. No fixture, denominator or target was changed to hide it. **Status (2026-10-21): fixed by decision 0021**, a worker-published lexical lookup the hook reads with the standard library within the same deadline (schema 11). The per-platform re-measurement and the Windows cold-cache verdict are recorded in the Task 11 follow-up checkpoint of BUILD_PROGRESS.

## Consequences

Wired now: the harness in both modes (live refusing under B1), the scripted agent and recorded curator, trials with evidence horizons, the workload days, the demonstrations, the report, the latency gate and the measurement workflow, the release build and workflow, the checklist and its checker, the operator guide, derived-body aging and the dependency label. Blocked by B1: every live trial, live workload execution, live extraction/review quality, live delivery certification and therefore the preview gate itself; the checklist verdict is `blocked`.

Failed and recorded at the time: the §7 usefulness targets on every native platform (item 15; since fixed by decision 0021, see its checkpoint). Not established: the Windows cold-cache p95, which was over 300 ms in one CI run and under it in another. The preview may be published only as an explicitly experimental build with these unmet targets stated. Full-only and not started: the 48-scenario three-trial comparison, held-out corpus and its independent authorship, the Breadcrumbs and notes baselines, Task 14, upgrades/transition, transfers and capsules.
