# Decision 0004: Capture spool, source cursors and normalization details

Status: accepted (Task 3) · Date: 2026-10-16

## Context

SYSTEM_SPEC §5.1–5.3 and DATA_CONTRACTS §2 fix the durability order (scrub, temp write, flush, atomic rename, acknowledge, then cursor) and the bounded-text rules. They leave several concrete representations open: where a durable cursor lives when hooks cannot write SQLite, how the head/tail display string relates to `text_chunks`, what `ingest_ready`'s `limit` counts, and the IDs of segments and environment observations. Task 3 needed one answer for each, and Task 3b must reuse the same spool format.

## Decisions

1. **Spool layout.** `.recalith/spool/` holds `tmp/` (private temp segments), `ready/` (published segments named `<created_at compact>-<segment_id>.seg.json`, ingested in name order), `cursors/` (one `<source_id>.json` per source), `gaps/` (content-free capture-gap records for health), and `quarantine/` (invalid or foreign segments, never ingested). Directories are created 0700 and files 0600 on POSIX. Existing directory modes are never changed. `storage/spool.py` and `storage/failpoints.py` are standard-library only, so Task 3b's fast path uses the same publication code.
2. **Durability per platform.** POSIX fsyncs the file and then the directory after rename and unlink. macOS uses `F_FULLFSYNC` where available. Windows cannot fsync a directory, so it relies on NTFS metadata journaling and reports `dir_synced: false`. Only a recognized transient sharing/access error (winerror 5, 32 or 33) on Windows gets the single retry. The retry waits at most 20 ms and never longer than the remaining soft deadline. A finished durable publication is still acknowledged after the deadline, and the receipt then reports `capture_deadline_overrun`. Power loss on hardware that ignores flushes remains outside what the spool can detect.
3. **Two cursor records.** `capture` writes the durable cursor file atomically, and only after every segment of the call is published. Ingestion copies the segment's cursor proposal into `capture_sources.ingested_cursor`/`durable_cursor` in the same transaction as the events. Recovery resumes from the furthest of the two (ordered by `(generation, offset)`), and neither ever moves backwards. A lost cursor write therefore only repeats events, which identity deduplicates (A05).
4. **Source files.** A source is one exact absolute path registered from a session payload. A final-component symlink is refused, and reads use `O_NOFOLLOW` where available plus an identity re-check. The cursor is `{generation, offset, identity, tail_digest, line}`. Only complete lines are consumed. Truncation, rewriting, or replacement with different content starts a new generation from offset 0 with an explicit gap. A replacement that keeps the consumed bytes continues in the same generation. Without a host event identity, the key is `<source_id>:<generation>:<offset>:<subindex>`.
5. **Bounded `result_text`.** When output exceeds 16 KiB, `result_text` stores `head + "\n[recalith: N code points omitted]\n" + tail`. The contract's +256-byte allowance covers that marker. `text_chunks` hold the head (`result_text_head`) and the tail (`result_text_tail`) as exact spans with original code-point offsets. Locators address chunks, never the display string's marker. The omitted range is the gap between the two chunks, and `coverage.truncated` is set. This stores the retained text twice, at most 16 KiB extra. That choice keeps a readable `result_text` for every consumer and exact addressable spans for capsules. Structured fields win over diagnostic text: if the event would exceed 64 KiB, head and tail shrink first, then long argument strings are bounded, and otherwise the event is refused.
6. **Assertions and runtime versions.** Normalization drops host- or model-supplied `assertions`, `error_signature` and `text_chunks`, and computes them again from `capture/parsers.py`. That module holds certified parsers for pytest summaries, the unittest runner, and exact `python --version`/`node --version`. An `exit_status` assertion comes only from the host's structured exit code. Ingestion never trusts a stored `parsed_value` assertion for runtime provenance. It reruns the certified version parser on the stored output of an exact `observed_tool` invocation. A raw `expected_red` hint is dropped with an `expected_red_hint_dropped` warning.
7. **Coverage detail.** The envelope keeps its four coverage booleans. Content-free warning counts go in `extensions[<adapter_id>].coverage_warnings`, for example `redacted`, `result_text_bounded`, `environment_dropped:<unregistered>`, `parser_unrecognized:<parser>@<v>`. Gap records and receipts hold reasons and counts only.
8. **Identity-field secrets are refused, not rewritten.** A credential-shaped value in `source_event_key`, `host_session_id`, `adapter_version` or the origin locator makes that event `policy_refused`. Scrubbing it would change event identity. The error never repeats the value.
9. **Oversized messages** in `user_message`/`assistant_message`/`generic_observation` are split into ≤48 KiB parts. Part 0 keeps the source key, part *i* uses `<key>#p<i>`, and each part carries `text_part = {source_field, index, count, original_start, original_end}`.
10. **Platform environment.** `session_started`/`generic_observation` payloads may carry `environment`. It is reduced to registered keys and values. Runtime keys are removed from platform facts, because only operator config or a certified tool observation supplies them. Ingestion turns the remaining `os`/`arch`/`ci` into `adapter_platform` observations.
11. **IDs.** Segments use the new `seg_` prefix (UUIDv4). Environment observations use `obs_` + SHA-256. Executables use `exe_` + SHA-256 of installation, workspace and identity. The executable registry matches the action's exact `executable` string, and its fingerprint must be a SHA-256 digest.
12. **Receipts and limits.** `capture` never opens the store, so it never answers `duplicate`. Duplicates are resolved at ingestion. A call that spans several ≤256 KiB segments names the last segment in `segment_id` and all of them in `coverage.segment_ids`. Cursor proposals ride only in the last segment. A failed later segment returns `not_captured`, and earlier segments replay harmlessly. Foreign or underived event identity fails the whole call. `ingest_ready(limit)` bounds the number of **segments** per call, and each segment is one transaction.
13. **Follow-on job.** Each ingested segment that inserted new events creates one deterministic `ingest` job (budget pool `none`). Its idempotency key follows DATA_CONTRACTS §8, so replays create nothing. Conflicting payloads advance `guidance_epoch`, and their rows are listed by `capture_health`. Suspending claim-level caution for a conflicted source is applied once claims exist (Tasks 5/10).
14. **Failpoints** are armed only programmatically, inside the test process (`failpoints.arm`). No environment variable or flag can arm them.

## Consequences

Task 3b moves no logic. It imports the stdlib spool and redaction modules from the fast path, or relocates them under `recalith.fast` unchanged, and emits the same segment format. Health (Task 17) consumes `capture_health()`. The crash protocol test harness lives in `tests/integration/capture_scenarios.py` and defaults to 3 repetitions per failpoint. The nightly workflow runs 20, and a release candidate sets `RECALITH_CRASH_REPS=100`.
