# Decision 0010: Evidence lineage, root classes and applicability

Status: accepted (Task 8) · Date: 2026-10-17 · Host observed: Claude Code 2.1.301 fixtures (capture); no live route (B1)

## Context

Task 8 builds `core/lineage.py` (`independent_roots`) and `core/conditions.py` (`evaluate_conditions`) under SYSTEM_SPEC §5.3, §7.1, §7.1.1, §7.1.2, §7.3, §7.4 and §13, and DATA_CONTRACTS §1.1, §2.1, §6, §6.1, §9, §10 and §11. The documents fix the rules: eligible roots, equivalence by exact descriptors (origin, provenance, artifact snapshot, experiment signature, same authority, unknown dependencies), canonical `root_` IDs with aliases, conservative unknown coverage, contradictions that block corroboration, tri-state AND with exclusions, exact paths and `/` prefixes, the nonsecret environment allowlist, PEP 440 ranges through `packaging`, and branch predicates distinct from branch annotations. They leave open where descriptors come from when an adapter sets none (the Claude 2.1.301 adapter sets `observation: null`), how classes stay a transitive closure across the store, when classes are written and what a merge triggers, how forwarded subagent output is traced on the real host, which tool results are not observations at all, what "exact comparison" means for an unparsable version, how a query names its branch, and what admission enforces now. Task 8 needed one answer for each. Nothing here weakens a rule; where a rule was ambiguous the stricter reading was taken.

## Decisions

1. **Descriptors are built by lineage code from the stored envelope.** `lineage.classify` derives the canonical `ObservationDescriptor` from the scrubbed, bounded, stored event (never from model output and never on the hook path, which stays unchanged). An adapter-set descriptor is honored only when its `origin_event_key` is the event's own; `complete` coverage is honored only for an adapter in `CERTIFIED_EXPERIMENT_ADAPTERS` (empty in this build: no complete-dependency domain is certified) with a nonempty, fully fingerprinted dependency set and an exact action, else it is downgraded to `partial`. A malformed or foreign-origin descriptor makes the root **unresolved**. Host facts live in the data table `ADAPTER_LINEAGE` (the domain layer imports no adapter module; a test checks it against `fast.claude_capture`): for Claude 2.1.301 a complete, untruncated, successful `Read` of exactly one workspace path is an artifact snapshot (`file:<path>`, digest over the stored arguments and result text); a `Task`/`Agent` result forwards the subagent named by its `agentId`; every other certified result is a tool result whose dependencies are unknown.
2. **Eligible roots.** `user_message`, `operator_declaration` and `operator_correction` on the user channel with `explicit_user` authority (observation kind `user_declaration`), and `tool_finished`/`artifact_changed` on the tool channel with `observed_tool` authority, without `derived_from`. Never roots: memory telemetry (no traversal either), derived events (resolved through `derived_from`), assistant text, events without user/tool authority (uncertified host versions, the host `<task-notification>` prompt, session lifecycle, compaction), a `tool_started` call without its result, **self-reporting commands** (`echo`/`printf` with an exact argv: agent text routed through a tool, so a memory echoed through Bash cannot confirm it) and **forwarded subagent output**.
3. **One actor without verified authority.** Every user statement in an installation has `authority_actor_id = user:local`. Per proposition, all user declarations of one actor collapse into one class (`same_authority`); quoting text on the user channel never creates a second authority. An invalid proposition key collapses all support into one class. Whether a sentence is a declaration (quoted, pasted, fenced regions) stays Task 9 review.
4. **Classes are a persisted transitive closure (schema 4).** Ingestion registers every eligible root event in the same transaction as the event (`lineage.register_event`, called from `capture.pipeline.ingest_ready`): `root_event_members` (event → origin key, observation kind, authority actor, outcome, resolution), `root_members` (origin → class, canonical descriptor), `root_tokens` (exact equivalence key → class) and `root_classes`. Tokens: origin identity (message parts share one origin); artifact (workspace, key, digest); experiment signature (workspace, normalized action, experiment identity, sorted complete dependency fingerprints); otherwise one unresolved family (workspace, normalized action, experiment identity). The normalized action is tool + executable + argv in order + cwd for an exact parse, tool + stored arguments for a structured tool, and a single `unresolved` signature per tool for an unparsed or conservative parse (differing unknown fields never split it). A lineage-certified snapshot has no family token; an adapter-set artifact with an action keeps its family token, so an adapter cannot split a family with varying digests. No token holds a destination installation, delivery count, session, tool-call or run ID, or a timestamp. An unresolved root carries only its origin token.
5. **Class IDs and aliases.** A class ID is `root_` + SHA-256 of the canonical JSON `[source_namespace, source_event_key]` of its lexicographically least member (`source_namespace = <installation_id>:<adapter_id>` for local events: the original producer, never a destination). When a smaller member joins or classes merge, the surviving ID is recomputed, members/tokens/aliases move to it, and each replaced ID is kept in `root_aliases` (flattened). `resolve_alias` resolves stored IDs; counting reads current members, so it never returns an alias or an event ID.
6. **Merges trigger revalidation.** When one new event shares tokens with two or more existing classes, the classes merge; counts can drop. In the same ingestion transaction (failpoint `roots.after_merge`, family `failpoints.LINEAGE`) the guidance epoch advances and the live claim heads whose current revision cites a member of the merged class as support (directly, or through one task/episode/claim) get a coalesced `revalidate` job (protected pool, batches of 8). A join or a representative change alone is not serving-relevant. The revalidation decision itself is Task 10.
7. **Counting** (`lineage.resolve` → `Lineage`; `independent_roots` returns its `support_classes`). Support and contradiction links are traversed separately through stored provenance with cycle detection (a ref already on the path is cut and counted in `cycles`) and bounds (32 levels, 2,048 nodes, 512 forwarded events; exceeding them sets `incomplete`). An event link uses the event's provenance; a record link uses the located `SupportedText`'s evidence when its locator names one, else the record's `supports` (claims) or all its `supports` evidence (tasks, episodes; `context` links never count), restricted to the link's named `root_event_ids` when present. A forwarding result resolves to the tool results recorded in the same host session with its subagent's `agent_id`; a `forwarded_origin_keys` descriptor resolves to those origins' members. Unresolved roots add no class beside a resolved one and form at most one alone. A root whose source identity has an unresolved `source_conflicts` row is excluded (`conflicted_roots`, `needs_revalidation`). A class whose members hold both a success and a failure is unstable, as is a class on both sides. `corroboration_blocked` is set by any contradiction class, unstable class, conflicted root, cycle or incomplete traversal. Distinct classes are a necessary condition, not proof of independence.
8. **What admission enforces now.** (a) A support link is attached to an existing claim (`attach_evidence`, or a duplicate `propose_claim` merging into its head) only when it raises the claim's class count for its proposition; otherwise nothing is written (`duplicate_evidence` when it resolves to a class already present, `no_independent_root` when it resolves to none). Contradicting links keep link-identity deduplication, so a contradictory rerun from the same class stays attached. (b) `last_supported_at` is the latest observation time (occurred, else recorded) of the roots of the classes that last raised the count; repetition never advances it. (c) A record link (task/episode/claim) may name only roots its stored provenance reaches (`root_mismatch`), matching the Task 5 rule for event links. Strength assignment, semantic admission, mapping validation and review admission remain Task 9 (`assess_claim` is unchanged; claims stay weak candidates).
9. **Applicability** (`core/conditions.py`). Tri-state Kleene AND over conditions (any `false` → `false`, else any `unknown` → `unknown`); `exclude` negates a known result and leaves `unknown`. Paths: exact, or a prefix when the value ends in `/`, against the query action's paths only for an exact parse; a name equal only after NFC normalization and case folding is `unknown` (Windows/macOS may treat it as one file; nothing is lowercased); `""`/`.` are unknown. **Contract fix:** a path condition containing `* ? [ ] { }` is refused by the `Condition` validator (DATA_CONTRACTS §1.1: no model-authored globs). `environment_equals`: exact string over registered keys; missing or the value `unknown` is unknown. `version_range`: inclusive `[value, upper]` (no `upper`: unbounded above) by `packaging.version.Version`; an unparsable version is unknown unless the condition specifies **exact comparison** (`upper == value`), which compares exact strings; an inverted range is unknown; no lexicographic fallback. `action_kind` needs an exact parse; `tool` uses the host-reported tool identity. Scope (`scope_applicability`): workspace, task, paths and environment combine with AND, values with OR, empty is unrestricted, `branch_refs` are never consulted; `applicability` evaluates scope before conditions, and `in_scope` filters candidates before any similarity ranking. `dependency_applicability` is the failure-lesson gate: empty or unfingerprinted dependencies and missing current values are `unknown`, any changed fingerprint `false` on any branch, all matching `true` across branches. `advice_for` yields a caution only for `true` and current freshness. Query environments come from `capture.provenance.environment_values`, which omits missing, stale, unbound and conflicting runtime values, so those evaluate unknown.
10. **Contract addition: `ContextQuery.branch_ref`** (optional, default null): the current branch, used only by explicit `branch_ref` conditions; null is unknown. Schemas regenerated; the hook wire tables are unchanged (the hook query is still null in capture-only builds).
11. **Schema 4.** Migration `0004.sql` adds `root_event_members`, `root_tokens` and indexes on the existing `root_members`/`root_aliases`; `SCHEMA_VERSION` becomes 4. A schema-3 development store is refused (`invalid_schema`, "requires an explicit migration"), never migrated silently (decisions 0007–0008; the upgrade path is Task 17). The new tables hold identities and digests, no event content; Task 16 forgetting must still remove their rows for forgotten events.

## Consequences

Task 9 consumes `lineage.resolve` for strength (`corroborated` needs at least two `support_classes` and not `corroboration_blocked`; declarations alone cannot exceed `supported`), mapping validation and declaration review; Task 10 owns what the queued `revalidate` jobs decide, `FailureRecheck`, and the dependency index that applies `dependency_applicability`; Task 11 uses `applicability`/`in_scope` before ranking and `advice_for` for packet items and precomputes version results for hooks only with exact consulted fingerprints; Task 12b supplies `branch_ref` and session-scratch invalidation in queries; Tasks 15/16 make the root tables participate in retention and forgetting; full-release imports reuse origin keys and aliases (`evt_imp_` stubs are not yet built). No host or provider certification follows from this work: B1 still blocks live certification.
