# Decision 0005: Capture-only Claude adapter and the stdlib fast path

Status: accepted (Task 3b) · Date: 2026-10-16 · Host observed: Claude Code CLI 2.1.301 on Linux

## Context

Task 3b builds the synchronous hook boundary: stdlib-only capture of real Claude Code events into the Task 3 spool, with delivery disabled (DATA_CONTRACTS §2.3; SYSTEM_SPEC §5.1–5.3, §9.2). The contracts left open where the shared stdlib code lives, how the fast validators stay equal to the strict models, how a hook registers a transcript without SQLite, and how the hook learns its installation and the host version. Real 2.1.301 payloads, captured by `tools/capture_claude_fixtures.py` into `tests/fixtures/hosts/claude/2.1.301/`, settled the event mapping. They also exposed host behavior that the design had not anticipated.

## Decisions

1. **One stdlib package.** `recalith.fast` holds the spool, failpoints, redaction, certified parsers and the normalization core, together with the wire layer, session scratch, the Claude adapter and the entry point. `storage/spool.py`, `storage/failpoints.py`, `capture/redact.py` and `capture/parsers.py` were moved unchanged except for their imports. Each old name is now an alias for the same module object (`sys.modules[__name__] = impl`), so arming a failpoint or patching an attribute through either name is identical. Fast modules avoid `dataclasses` (about 20 ms to import) and `typing` (about 3 ms). The import inventory is checked in fresh processes (`tests/platform/test_hook_imports.py`).
2. **One normalization implementation.** `fast.normalize.normalize_raw` builds envelope dicts. `capture.normalize.normalize_event` calls it and validates the result into strict `EventEnvelope` models. Both paths therefore produce byte-identical envelopes, IDs, digests, chunks and warnings by construction, and the agreement test checks this on every real payload. `RawEvent` gains `adapter_coverage`, which carries adapter-observed flags such as host truncation into the event's coverage.
3. **Generated validators.** `tools/generate_hook_wire.py` derives `fast/wire_generated.py` from the strict models' JSON Schema. It adds every field check by name (`id`, `digest`, `utc`, `portable_path`, `json_object`, `environment`, UTF-8 byte caps), every model validator by qualified name, and the defaults Pydantic fills on dump (segment digests are computed over dumped envelopes). `fast/wire.py` interprets the tables and mirrors the nine model validators by hand in `RULES`. Generation fails if it meets a schema keyword, field check, before-validator or model rule with no stdlib equivalent. `--check` runs in CI. Verdict agreement is tested on the shared fixtures and on a mutation corpus of 860 single-field variants of the valid fixtures, including every channel×authority pair and every event kind.
4. **Strict literals are type-exact (contract fix).** Pydantic's literal validator accepts `true` and `1.0` for `Literal[1]`, and `0` for `Literal[False]`, even in strict mode. As a result, `schema_version: true` and `expected_red: 0` passed strict validation, contrary to DATA_CONTRACTS §1 ("no coercion"). The mutation corpus found this. The ten literal fields now use an exact-type before-check (`One`, `ExactBool` in `contracts/common.py`). The invalid fixtures `schema_version_boolean.json` and `expected_red_zero.json` pin the fix, and schema snapshots are unchanged.
5. **Transcript registration rides in the segment.** Hooks cannot write SQLite, so a segment may carry `source_registrations`: up to 8 `SourceRegistrationProposal` entries of `{source_id, adapter_id, session_id, host_session_id, source_kind, locator, parser}`. They are included in the content digest only when present, so earlier segments keep their digests. Ingestion re-derives the canonical locator and source ID, refuses links and non-regular files, and inserts idempotently in the same transaction as the events. A refusal becomes a content-free gap. The locator never enters an event payload.
6. **Hook context manifest.** `.recalith/run/hook-context.json` (private) holds IDs, root and workspace paths with their device:inode identities, the policy revision, and the host version recorded for each adapter. `capture.hooks.write_hook_context` writes it from an already resolved `InstallationContext`. Task 13's `integrate` will call it, and until then tests and tools do. The entry validates the manifest and requires both identities to match: a copied or moved checkout is `installation_relocated` and nothing is written. A missing manifest is `capability_unavailable`. The entry forces `delivery_enabled` false in this build.
7. **Claude 2.1.301 mapping** (`fast/claude_capture.py`). `SessionStart` maps to `session_started` (`startup`, `resume`, `clear`). `SessionStart(source=compact)` and `Pre/PostCompact` map to `compaction`, with phase `context_restored`, `pre` or `post`; the model's compaction summary is not stored. `UserPromptSubmit` maps to `user_message`, except that a prompt starting with `<task-notification>` is host-generated and becomes a `generic_observation` without user authority. `PreToolUse` maps to `tool_started` and `PostToolUse`/`PostToolUseFailure` to `tool_finished`. `Stop` and `SubagentStop` map to `session_stopped`, and `SubagentStart` to `session_started` (scope `subagent`). `SessionEnd` maps to `session_ended`. Every other event, including the observed `PermissionRequest`, which has no `tool_use_id` and no outcome, leaves an explicit `unsupported_host_event` gap. Payload fields outside the recorded 2.1.301 field set leave `unsupported_host_field` and incomplete parser coverage.
8. **Identity.** `session_id = sess_` + SHA-256 of `[installation, adapter, host session ID]`. Tool events key on the host `tool_use_id`, which gives each call an immutable identity, so a late or early result joins its call. `prompt_id` is reused across queued prompts on 2.1.301, so events without host identity key on the session, event, qualifier and the transcript's byte length when the hook fired: the record position in the registered source.
9. **Exit codes and host truncation.** An exit code comes only from a Bash failure's host prefix `Exit code N\n` on a certified version. `PostToolUse` never implies exit 0, because the host reports `grep` exit 1 as success with `returnCodeInterpretation`. The host head-caps Bash stdout at 30,000 characters (`persistedOutputSize` exposes the original size) and middle-truncates failing output to about 10,000 characters with a marker. Both set `coverage.truncated` and `missing_context` with a `host_output_truncated` warning. Recalith does not read the host's `persistedOutputPath`. A68 therefore holds on what the host delivers. A failure line at the end of output above about 30,000 characters is lost by the host before any hook or transcript sees it, and that event is recorded as incomplete, not as complete evidence.
10. **Commands (A70).** A Bash command gets an exact argv only when it holds plain words and quotes and no pipe, redirection, expansion, glob, escape, comment, compound command or leading assignment. Otherwise it is `parse_status: unknown` with no executable or argv. `raw_digest` hashes the scrubbed command, because hashing a low-entropy secret would expose it to brute force. Structured host tools (Read, Write, Edit and others) are `exact` with workspace-relative paths. Unregistered tools, such as a PowerShell tool, are `conservative`. Absolute path *fields* inside the workspace become relative. Paths inside free text, such as host error messages, are kept as given.
11. **Unknown host versions** are captured in conservative mode: no user or tool authority, no version-specific exit-code parsing, and incomplete parser coverage (SYSTEM_SPEC §9.2).
12. **Transcript supplement.** `transcript_line_parser` handles registered 2.1.301 transcripts and maps only non-empty assistant text, keyed by the record `uuid`. No 2.1.301 hook delivers that text completely, and hooks capture everything else, so the supplement and the hooks never produce the same content under two identities. Known metadata record types are skipped. An unknown type raises `RecordGap`, which `read_tail` records as an explicit gap. The worker drives recovery from Task 4.
13. **Hook launcher.** `init` writes `.recalith/bin/recalith-hook` (POSIX) and `recalith-hook.cmd`. Without the pinned runtime, the launcher drains stdin and exits 0 silently, with no download, output or hint. SYSTEM_SPEC §2.2's optional one-time bootstrap hint is not implemented. With the runtime, it runs `python -I -m recalith.fast.entry`.
14. **Deadline and scratch.** One monotonic soft deadline starts at entry + 250 ms. Durable publication is never abandoned once begun, and the receipt reports `capture_deadline_overrun`. The clock cannot bound a blocked `fsync`. The post-tool typed-outcome overlay is shed first (`deadline_overlay_skipped`). It runs under a per-session OS lock with at most 20 ms of wait (`scratch_lock_timeout`) and an atomic replace. It is bounded to 32 outcomes and 128 KiB, its outcomes are scrubbed, and it is discarded at `SessionEnd`. Lock files are retained so a waiter can never lock an orphaned inode, and they are pruned with idle scratch after 24 hours. `handle_hook` skips `hook_capture`'s payload re-scan only for envelopes normalized in the same call. Other callers' envelopes are re-scanned, and the service `capture()` keeps its own re-scrub.
15. **Rejections.** Any `RECALITH_CURATOR_INSTALLATION` marker means a curator-owned session: nothing is captured. A hook `cwd` outside the registered workspace, proven by file identity, is a `foreign_workspace` gap. The hook always exits 0 with empty stdout.
16. **Parser version.** `pytest_summary@2` additionally recognizes the bare final line printed by `pytest -q` (`1 failed in 0.01s`), which real 2.1.301 payloads contain. The body must consist only of count items.

## Consequences

Task 4's worker runs `recover_source` with the transcript parser registered for each source's `parser`. Task 12b adds the delivery branch to `handle_hook`; Task 13 writes the hook entries and the manifest through `integrate`, adds the bootstrap hint if wanted, and certifies delivery paths. Hosts or versions other than 2.1.301 need their own fixture capture before their mapping is certified. Capture-only latency is in `docs/measurements/hook-latency-capture-only.json`.
