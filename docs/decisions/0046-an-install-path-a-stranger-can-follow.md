# Decision 0046: An install path a stranger can follow

Status: accepted (Tasks 2, 12a, 13, 17 and 18, preview) · Date: 2026-11-09 · Engine: `0.1.0.dev14` · Observed: the pre-publication audit of `0.1.0.dev10` ([report](../audits/2026-11-06-memory-system-audit.md), Phase 3 of [the fix plan](../audits/2026-11-06-fix-plan.md))

## Context

The audit tried to install Recalith from the documents and the release artifacts alone and could not.

- **CLI-1, CLI-2 (high): the quick start was circular.** `bootstrap.py install` required `.recalith/project.toml`, which only `init` writes, which was reachable only through the launcher `init` creates; on a fresh clone it died in `mkdtemp` with a raw `FileNotFoundError` because only `init` creates `runtime/`. The wheel installed no `recalith` executable. The pre-init refusals named a "release init entry point" that did not exist, although SYSTEM_SPEC §13.1 and DATA_CONTRACTS §12 promise bootstrap pre-init `init` and `operator-token` forms.
- **REL-1 (high): a release could not be installed by its own documented route.** The release workflow uploaded the wheel, sdist, digests and manifest but not `bootstrap.py`, `requirements.lock` or any wheelhouse; the wheelhouse recipe lived only in `ci.yml` and is specific to the platform and Python minor version that ran it.
- **CLI-3 (high): `integrate claude` edited a tracked settings file.** `_git` looked for `.git` at the project root only and read any nonzero exit as "not tracked"; it also overrode `HOME`, so the user's `safe.directory` entries were not read and git reported dubious ownership. In a monorepo subdirectory, or under that error, a tracked `.claude/settings.local.json` received 216 deny rules and 11 hook groups.
- **CLI-4, CLI-5, CLI-7 (medium, low):** `--remove` failed forever over a whitespace-only before-copy; a symlinked settings file was replaced by a regular file; the user's settings file became 0600, and the tracked `.recalith/` files were 0600 too.
- **CLI-6 (medium): nobody was told where the curator key lives.** The hook-started worker inherits Claude Code's environment and forwards only the route's key names, so the curator works only when the key is exported in the shell that launches Claude Code; the documents said to export it "in that terminal only" for the probes.
- **REL-10 (medium): `status` printed hundreds of JSON lines** and seven reason codes with no summary or next step.
- **Small:** the notice told Windows users to run the `sh` launcher; the POSIX hook launcher showed the host a traceback on every event when the venv could not import the engine; `init` on a clone silently ignored `--profile`; `doctor --full-integrity` ran unguarded although the contract says it is guarded and it writes a checkpoint; three registered error codes fell back to exit 5; `operator-token create --project` left the token file behind when registration failed; the bootstrap deleted an unmarked runtime tree a worker might run from; the metadata lacked urls, authors, classifiers and keywords; "216 deny rules" was the POSIX count.

## Decisions

1. **The bootstrap has the pre-init forms** (`bootstrap.py`, standard library only): `install` provisions for a new project (no `project.toml`) and for a fresh clone alike, creating `.recalith/` and `runtime/` owner-only before staging; `init` and `operator-token create` provision when needed and then run exactly that `recalith` form on the provisioned interpreter with the caller's standard input and environment (POSIX `execv`; a child process on Windows, where exec would detach from the console), so the guard judges the same caller and the exit code is the CLI's. A missing wheel, wheelhouse or `requirements.lock` is named (4); an `OSError` is 5; a runtime directory without a provisioning record is refused (2), never deleted.
2. **A release is a directory a stranger can install from:** the wheel, the sdist, `bootstrap.py`, `requirements.lock`, `SHA256SUMS`, the manifest, and one `wheelhouse-<platform>-<python tag>/` per supported platform and Python version. `tools/build_wheelhouse.py` downloads exactly the locked wheels for one interpreter, names the directory for its platform and tag, refuses to mix, checks every digest against the lock and writes `WHEELHOUSE.json`. `tools/build_release.py` copies the bootstrap and the lock beside the wheel, verifies every wheelhouse in `--out` against the lock, and digests all of it. The release workflow builds wheelhouses on Linux and Windows for Python 3.12 to 3.14, assembles them, and installs from the layout alone, offline, to `status` exit 8 before uploading.
3. **The wheel installs a `recalith` console script** (`recalith.cli.main:main`), and the metadata names authors ("Recalith contributors", until the owner chooses the holder), urls, classifiers (3.12 to 3.14, OS Independent, Alpha) and keywords. The pre-init refusals and the launchers name the `bootstrap.py init` form.
4. **Tracking is judged by the repository that holds the project.** `git rev-parse --show-toplevel` from the project root, with the user's own configuration (no `HOME` override) plus `-c safe.directory=<root>`, decides whether a repository exists; `ls-files --error-unmatch` then decides tracking. Exit 0 is tracked, 1 untracked, "not a git repository" no repository, anything else `unknown`, and unknown is refused (`policy_refused`, `settings_tracking_unknown`), never read as "safe to edit". The ignore state is verified the same way.
5. **A symlinked settings file is refused, naming its target,** on install and on removal, and `atomic_write` refuses a link as a last check. The settings file keeps the mode it had; a new one, the project `.gitignore` and the tracked `.recalith/` files are ordinary files (`0o666 & ~umask`; launchers 0755); Recalith's own records stay 0600 in 0700 directories. A whitespace-only before-copy is the empty object it was read as.
6. **`status` and `doctor` without `--json` print one screen:** readiness, engine and profile, each required capability that is not healthy with the meaning of every reason code and the action it implies (`operations.reasons`, the OPERATIONS §2 table as code, checked complete against every code health flags), the one next command (the curator route first, then the host, in the order of OPERATIONS §4), and where the full report is. The JSON form is unchanged.
7. **The curator key's location is stated** by `integrate claude` (`worker.key_location`), by OPERATIONS §4 and by `status`: the worker inherits the environment of the process that launches Claude Code. Health already judges a running worker's own route report (`source: worker`) before this terminal's environment (`source: configuration`); the human form says which one lacks the key.
8. **The small ones.** The notice names `recalith.cmd` on Windows. The POSIX hook launcher drops the entry's stderr and always exits 0 once the runtime exists (the entry keeps its own diagnostics), as the `.cmd` launcher did. `init` on a clone refuses a differing `--profile` or `--release-profile` (2). `doctor --full-integrity` is a guarded form (`doctor_full_integrity`) and a 19th administrative form in the deny rules: 228 rules on POSIX, 475 on Windows. `foreign_installation` exits 6, `event_identity_conflict` 3 and `backup_unavailable_after_forget` 5. A token whose registration fails is unlinked. OPERATIONS §4 is one complete, copy-pasteable sequence per platform, linking `docs/probes/LOCAL_CONFIG.md`.
9. **Engine `0.1.0.dev14`.** No adapter changed. The release checklist's smoke gate stays blocked (decision 0043).

## Rejected

- **Resolving a symlinked settings file to its target and recording the real path.** It would write Recalith's hooks into a dotfiles repository the user shares across machines; refusing is the smaller surprise.
- **Resolving a tracked settings file by installing into the shared file instead.** Shared, tracked hooks are the full-release `--shared` mode (decision 0018).
- **Keeping `doctor --full-integrity` unguarded and correcting the contract.** It writes the verifier's checkpoint; a form that writes is guarded.
- **Printing the human summary and the JSON report together.** Two forms, chosen by `--json`, keep machine stdout exactly one object.

## Tests

- `tests/integration/test_installations.py`: the bootstrap names the missing input and refuses a bad name or digest before creating anything; a fresh clone and an empty directory both fail cleanly (exit 4, no traceback, `runtime/` 0700, no staging left) with an empty wheelhouse; an unmarked runtime tree is refused; the pre-init forms provision and then run exactly `init` or `operator-token create` with the options passed through; tracked files are ordinary files; with a real wheelhouse (CI, and this checkpoint's walkthrough): a clone is provisioned and its launcher names the way in, and `bootstrap.py init` initializes an empty directory, `status` exits 8, a second init is refused and the runtime kept.
- `tests/unit/test_release_tools.py`: the wheelhouse check wants every locked wheel once with a locked digest; a wheelhouse is named for its platform and Python and never mixed; the release verifies each shipped wheelhouse and carries the bootstrap and the lock; every health reason code has a meaning.
- `tests/integration/test_claude_adapter.py`: a tracked settings file in a monorepo subdirectory is refused and its ignore state verified by the holding repository; a fake `git` that reports dubious ownership makes the state unknown, refused with nothing changed; a symlinked settings file is refused on install and on removal, the link and its target intact; a whitespace-only before-copy is restored byte for byte; the settings file keeps its mode and a new one is public; the notice names a runnable launcher; a runtime that cannot import the engine shows the host nothing; `integrate` says where the key lives; the launcher digests are re-pinned.
- `tests/integration/test_cli.py`: `status` and `doctor` without `--json` fit on one screen, explain the codes and name the next command, the machine form unchanged; `doctor --full-integrity` is refused without the guard and unavailable (4) after it; `init` on a clone refuses a differing profile; a token whose registration fails is not left behind; every registered error code has an exit code.
- `tests/integration/test_health.py`: from a key-less terminal, inference is judged by the running worker's own route report, and the text says whose environment lacks the key.

## Limits

- **The Windows sequence in OPERATIONS §4 was not walked here.** It is written from decision 0027's native-Windows pilots; the release workflow's install-from-layout step runs on Linux only. The owner's next live gate walks it.
- **`pipx run --spec recalith-*.whl recalith --help`** was not run (no pipx here); the console script was exercised through the project venv.
- **The holder name (REL-8) is the owner's decision.** `authors` says "Recalith contributors" until then; the repository URL in `[project.urls]` is the current one and changes if the package is renamed before publication (decision 0001).
- **The fake-`git` test covers the refusal, not every real git error class.** Any exit other than 0, 1 or 128-with-"not a git repository" is unknown by construction.

## Consequences

The owner provisions a fresh pilot from the `0.1.0.dev14` release layout before any live run, following OPERATIONS §4 as a stranger would, and reports where the page fails them. Phase 4 (public-repository hygiene) is next.
