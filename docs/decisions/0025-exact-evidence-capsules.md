# Decision 0025: Exact evidence capsules, link redirection and retained pins

Status: accepted (Task 15 full capsule slice, Cut 2) · Date: 2026-10-23 · Observed: deterministic tests on real captured events, recorded proposals, the real retention sweep, forget, backup and restore in full-profile fixture stores; no live route needed (B1 still open)

## Context

SYSTEM_SPEC §11 adds exact evidence capsules to the full profile: a pinned payload past the 30-day unpinned window may be replaced by a capsule holding the exact required observation, its source identity and time, original field/start/end/digest, attribution and sufficient context. Capsule insertion, link redirection and payload removal commit together only after sufficiency and locator integrity pass; resolvers use the original coordinates and never slice a short capsule at old offsets; when preservation is not sufficient the pin stays. DATA_CONTRACTS §6 defines `EvidenceCapsule` and `CapsuleSpan`, resolver dispatch by `RecordRef.kind`, the capsule origin index for frozen refs, and `payload_state`/`evidence_availability` `capsule_only`. Migration 0001 reserved `evidence_capsules (capsule_id, source_namespace, source_event_key, content_digest, body)`.

The documents left open: what "sufficient" means for a reference without a locator, how much context a span carries, how an event maps to its capsule, which normalized links are redirected, what happens to a capsule when its last owner goes or its source is forgotten, how the semantic admission gates (mapping, declaration, failure derivation) read capsule-only evidence later, and how each profile reports it. This record settles them. The preview-to-full transition that will also use capsules (§10.1, Task 17 full) is not built here.

## Decisions

1. **Profile gating.** Only a store whose `installation_meta.release_profile` is `full` creates capsules. Preview keeps its 180-day behavior byte for byte: no compaction, no capsule rows, health keeps `capsules` `unavailable` (`deferred_full_release`), `show cap_…` is `capability_unavailable`. `init --release-profile full` stays refused; full stores exist only through the provisioning function with a full `ProjectConfig` (tests, decision 0024). The capsule-aware readers below are profile-independent because a preview store never holds a capsule.

2. **When compaction runs.** The worker's retention sweep (`retention.sweep`) runs, after its expiry transaction, one compaction transaction for the payloads that are pinned, `available`, strictly older than the installation's `unpinned_event_payload` window by capture time (30 days by profile default; an operator override wins) and at or before the owed cursor. Candidates are chosen in a read snapshot; the transaction recomputes the pins and every check. No model or network call runs in it: capsule creation is deterministic storage work, not a model admission and not fresh support.

3. **Sufficiency** (the pin is retained, and the reason counted, unless every rule holds):
   - `owed_work`: unfinished work reads the whole payload: events not yet reduced or examined by the failure debounce, an unfinished job's event, task or episode inputs (and what they reach), the observation of a pending recheck, the failure of an undebounced trigger. A job whose input is a *claim* (a review or a revalidation) reads exactly what that claim cites, which the capsule keeps and the job's request carries (§6), so it does not block compaction; for expiry every owed event stays owed, as before.
   - `open_working_context`: a live task head (with its open working range) or an open episode reaches the event. SYSTEM_SPEC §11: open working context stays pinned.
   - `not_a_root`: the event has no `root_event_members` row. Only a registered root is compacted, because lineage reads a registered root's identity from the root tables and never its payload; an unregistered, derived, forwarding or telemetry event is read through its payload by the lineage walk.
   - `source_conflict`: an unresolved source conflict names the event (it needs an explicit resolution against the original).
   - Every reference to the event from a record revision the live claims' pin closure visits must be covered. A reference is an `evidence_links` row targeting the event:
     - with a locator: the locator must resolve exactly in the current payload (the stored field's slice hashes to the locator digest), else `locator_unresolved`; the capsule keeps that span;
     - without a locator but with a registered mapping: the event must be a certified tool result whose typed fields are preserved (below), else `mapping_unpreserved`;
     - without a locator or mapping: only where the contract defines a whole-field citation, i.e. a user or operator statement (`DECLARATION_FIELDS`: a null locator cites the whole `text`/`statement`), the capsule keeps the whole field as one span; any other unlocated reference names no span and is `unlocated_reference`.
   - Identity-only references (a link's `root_event_ids`, another event's `derived_from`/`root_event_ids`) need no payload text: the root tables keep the identity.
   - After building, the capsule is validated (`EvidenceCapsule`; each `CapsuleSpan` hashes to its digest and the original locator digest and has the locator's length) and every reference is resolved through it to the same text as the payload; any difference is `verification_failed`. A failed check retains the pin and never changes the claim.

4. **Capsule content.** `capsule_id = derived_id("cap", ["evidence_capsule", event_id])`: deterministic, so the event-to-capsule origin index needs no new column or index and no schema migration. `source_ref` is the event's origin; `origin_event_key` its lineage origin key; `root_event_ids` `[event_id]`; `captured_at` its capture time; `scope` its workspace; `redacted` its coverage flag; `content_digest` the digest of the canonical capsule without that field. The row stores the origin key in `source_namespace`/`source_event_key`, the digest, and the canonical capsule JSON as `body`.
   - **Spans.** One per distinct referenced locator (field, start, end, digest), sorted, with `origin_ref` the event. `context_before`/`context_after` are at most 160 code points of the same stored field, which was scrubbed at capture; context never becomes evidence.
   - **`preserved_observation`** (code-derived, no prose): `schema`, `event_id`, `event_kind`, `channel`, `authority`; for a tool result `tool` = `{tool_name, action, result_received, outcome, exit_code}` and `assertions` holding only the referenced assertion objects by index; for a statement event `statement` = `{field, length, text_part_count, regions}` where `regions` are the code-point ranges of the text's nondeclaration regions (offsets only), so the declaration check can be repeated exactly on a span after the text is gone.
   - The event row keeps its envelope metadata (kind, channel, authority, origin, session, coverage) as an expired event does; `payload` becomes NULL and `payload_state` `capsule_only`.

5. **Redirection.** In the same transaction every claim-owned `evidence_links` row targeting the event that the capsule covers becomes `target_kind = capsule`, `target_id = capsule_id`, `target_revision = 1`, keeping its locator (the original coordinates), mapping, relation and roots. Task and episode revision links, uncovered rows of historical revisions and every frozen ref in revision and proposal bodies stay event refs and resolve through the origin index (the reducer's open-range query and working memory are unchanged). The transaction writes a content-free `retention_capsule` operation (counts, event and capsule IDs, redirected link IDs, deferral reasons), advances the guidance epoch (rendering changes) and is a purge entry in the chain (decision 0024).

6. **Resolution** (`privacy/capsules.py`). The resolver dispatches by `RecordRef.kind`: an event ref reads the payload when `available`, the event's capsule when `capsule_only`; a capsule ref reads the capsule. A located reference is found by its exact original locator (field, start, end and digest) and returns that span's text; a capsule is never sliced at old offsets. A reference the capsule does not cover is unavailable. Consumers:
   - `lineage.chain_available` (admission and strength) accepts a `capsule_only` event that has a capsule and, for the cited event, covers the link; a capsule ref walks to its origin event (same root, same class).
   - `admission.check_link`, `check_mapping`, `declaration_refusal` and `derive_failure` read the preserved typed fields and statement regions; a capsule ref's roots may name only its origin event.
   - Rendering: a claim whose sufficient support is capsule-only renders `evidence_availability` `capsule_only` (servable as `context` per SYSTEM_SPEC §8.2); a disputed claim's quoted evidence uses the span text; `show` of an event adds its capsule and `show cap_…` returns the capsule (`capability_unavailable` in preview).
   - Model requests: `ModelRequest` gains `capsules: list[EvidenceCapsule]`, the capsules of the selected capsule-only events of the job's workspace, and `allowed_evidence_refs` adds each capsule's event and capsule refs. The field is omitted from the serialized request when empty, so every request without capsule-only evidence (every preview request) is byte for byte what it was. A later review or revalidation of a compacted claim therefore sees the exact cited spans, never an evidence-free request.
   - The readers of normalized links (`lineage.claims_citing`, extraction's relevant claims, `task_claim_ids`, forgetting's link index, the pin closure) treat a capsule target as its origin event.

7. **Admission and strength are unchanged by compaction.** No claim revision is written; strength, freshness, `last_supported_at`, roots and classes stay as they were. A capsule is never a root: a new link citing a capsule (or its event) resolves to the same root class, so it never adds corroboration.

8. **Release, expiry and forgetting.** When the last live owner releases a capsule-only event and it is past its window, the sweep expires it: the capsule row is deleted, links redirected to it revert to the event ref, and the event becomes `expired` (in the expiry transaction with the in-transaction pin recheck). Forgetting overrides pins: `release_payloads` deletes the capsule of every released event and reverts its links in the purge transaction; the closure finds owners through capsule targets; tombstone targets add the capsule IDs; a capsule ref is accepted as a forget selector in a full store and selects its origin event; a capsule-only root still counts as a surviving root of a quarantined derivative. Backups are SQLite snapshots and carry capsules; `backup.holds` counts a capsule of a forgotten event as held content, so affected backups are deleted, and suppression-aware restore purges the capsules of tombstoned events before the swap. Nothing is resurrected.

9. **Reports and health.** The sweep report adds `compacted_count`, `links_redirected` and `compaction_deferred` (reason → count). `RetentionSummary.deferred_compaction_count` keeps its meaning in both profiles: pinned payloads past the window still held in full (in full, those not compactable or not yet attempted). Health in a full store reports `capsules` `healthy` with coverage `{capsule_count, capsule_bytes, deferred_compaction_count, last_compaction}`; it is never required for readiness. Preview health is unchanged.

10. **Failure injection.** New family `failpoints.CAPSULE`: `capsule.after_plan` (candidates chosen, nothing written), `capsule.before_commit` (capsules written, links redirected, payloads removed, commit pending), `capsule.after_commit`. The full-profile kill/restart matrix (`test_full_profile_capsule_crash_matches_reference`: `CAPSULE`, `RETENTION`, `CHAIN`) requires a crashed compaction to reproduce the reference store, every live claim's evidence to stay resolvable and the chain to verify over every current row. Failpoints are armed only by a test in its own process.

## Limits (stated, not hidden)

- **Space.** A whole-statement citation keeps the whole statement; a tool result cited without a locator or mapping is not compacted (`unlocated_reference`). Capsules save space only where references are located or typed.
- **Pending model work under B1.** With no certified route, task and episode jobs never finish, so the events they read stay whole; claim reviews and revalidations do not block (§3).
- **Context for the curator** is the kept span with at most 160 code points either side; a model that wants more of the original observation cannot get it once compacted, which is the point of the space optimization.
- **Historical revisions** not reached from a live owner may lose evidence that no capsule kept; that is ordinary retention, as expiry already does.
- **Not built here:** the preview-to-full transition (Task 17 full), export/import of capsules and the Breadcrumbs importer (the rest of Task 15 full).

## Consequences

- No schema migration: `SCHEMA_VERSION` stays 11; existing preview stores and backups stay writable and restorable (not `migration_required`). The `ModelRequest` JSON schema snapshot gains the optional `capsules` property (regenerated); the hook wire is unchanged.
- A55 has its full variant implemented and tested but stays `pending`: a preview-excluded case is pending or unavailable until the full profile is reachable in a real installation (the manifest gate in `test_evaluation.py`). A35's full_only variant (capsule compaction, redirects, retained pins) is implemented and tested and moves to `in_progress`; nothing is passed. A21 gains the capsule kill/restart family.
- SYSTEM_SPEC §11 and DATA_CONTRACTS §6 point here for the details; DATA_CONTRACTS §7 (`ModelRequest`) and §12 (`show`) name the additions; IMPLEMENTATION_PLAN Task 15 records the built slice; OPERATIONS §3 lists the `capsules` health entry.
