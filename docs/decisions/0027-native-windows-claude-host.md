# Decision 0027: Native Windows as a Claude Code host

Status: accepted (Task 13 follow-up, preview; with the Task 3b capture review of 2.1.309 and a Task 7 adapter fix) · Date: 2026-10-23 · Observed: Claude Code CLI 2.1.309 on native Windows 11 (build 26200, NTFS, `LongPathsEnabled=0`), request-capture mode only (loopback scripted endpoint, placeholder key, private `HOME`; this session's credentials and proxy never used); no live route (B1 still open)

## Context

Every host observation so far was Linux: the capture fixtures (2.1.301–2.1.306), the engine-mode delivery certification and the deny-rule probe (decision 0019). Decision 0019 item 3 recorded that "Windows host execution of this POSIX command is uncertified, because no native Windows host is available"; the Windows CI job replays fixtures and runs the `.cmd` launcher through `cmd /c`, which is not how the host runs a hook. The owner's laptop is the first native Windows host. Before handing over the B1 operator commands, the hook path, the capture format of the installed version and the operator harnesses had to be shown to work there, or fixed with tests.

## Observations (request capture, Claude Code 2.1.309)

1. **Hooks run in Git Bash.** A hook printing its own shell reported `/usr/bin/bash`, bash 5.3.15, `OSTYPE=cygwin`; `$CLAUDE_PROJECT_DIR` expanded to `C:/…/workspace` (forward slashes); `%COMSPEC%` stayed literal (not cmd.exe). The Bash tool is the same Git Bash.
2. **The installed POSIX command was a silent no-op.** `"$CLAUDE_PROJECT_DIR"/.recalith/bin/recalith-hook claude_code --event E` ran the POSIX launcher, which looks for `runtime/<v>/venv/bin/python`; a Windows venv has `venv\Scripts\python.exe`, so the launcher took its "runtime not provisioned" branch: exit 0, no output, no capture, no worker start, no delivery. The same command naming the `.cmd` launcher reached the runtime's interpreter (Git Bash runs a `.cmd` through cmd.exe).
3. **Hook payloads and transcripts match 2.1.306.** `tools/capture_claude_fixtures.py` on this host: the same events and per-scenario counts in all four scenarios, identical field sets and value types in every payload (compared recursively), the same Bash prefixes, truncation sizes and persisted-output fields. Values differ only in identifiers, durations, Windows path separators and CRLF in output written by Windows Python subprocesses (pytest's lines; `seq` writes LF), plus pytest's terminal width. The adapter maps every record identically to the Linux 2.1.306 capture (outcome, exit code, parse status, truncation, chunk offsets, coverage; the background subagent as a multiset), and the transcripts yield the same assistant text records. Two benign differences also appear between 2.1.305 and 2.1.306: a transcript's size at hook time, and the order of a background subagent's start against its parent's post-tool hook. A `mode` transcript record, present since 2.1.301, is not in `KNOWN_TRANSCRIPT_TYPES`; in a real transcript it yields a content-free `unsupported_record_type` gap on every certified version (fixtures reduce it to a skeleton). Unchanged here.
4. **The capture sanitizer leaked on Windows.** The host's `/compact` output echoes each hook command as a JSON-encoded string, so Windows paths arrived JSON-escaped (`C:\\Users\\<login>\\…`, `C:\\Code\\…`) and the literal placeholders missed them; the host's own temporary directory (`%SystemRoot%\temp\claude`, node's `os.tmpdir()` for an environment without `TEMP`) had no placeholder. The tool's leak check tested only the raw form and passed.
5. **The engine-mode harness was Linux-only.** It linked the shared runtime with a symlink (Windows grants that privilege only in Developer Mode or to administrators: `WinError 1314` here), killed with `SIGKILL`/`killpg`, drove the deny probe through the POSIX launcher (exit 4 under Git Bash, before the guard), used a pty for the hangup case, and named fixtures so long that the host's transcript (`HOME\.claude\projects\SLUG\SESSION.jsonl`, SLUG = the whole workspace path) passed 260 characters (about 290; 324 for a subagent transcript), which Python cannot open without long-path support. Its report sanitizer had the same blind spot as item 4 for the absolute deny spellings in forward-slash, native and MSYS form.
6. **The worker survives, inside a job.** The hook-started worker (`windows_breakaway`) survived the session's end and a kill of the host's whole process tree (`taskkill /T /F`) and ingested afterwards, but it runs inside a Job Object (`in_job: true`): CPython's venv redirector (`Scripts\python.exe`) starts the real interpreter in its own job. The worker therefore honestly reports `degraded` (`job_membership_unverified`, decision 0006), and health flags the required `recovery` capability `worker_independence_degraded` while it runs.
7. **Path length.** With `LongPathsEnabled=0` a path stops at 260 characters (259 usable for a file, 248 for a directory). The 3.13 suite with a 128-character temporary prefix failed 857 tests on store and spool paths; with a 41-character prefix (the depth of CI's runner) two evaluation-harness tests still fail, because a trial's private host home holds `.claude\projects\SLUG\…` with SLUG repeating the workspace path; both pass from a base of 9 characters. GitHub's Windows runners have long paths enabled.

## Decisions

1. **What integrate installs on Windows.** On native Windows `recalith integrate claude` installs `"$CLAUDE_PROJECT_DIR"/.recalith/bin/recalith-hook.cmd claude_code --event E`; everywhere else the command is byte-identical to before. No launcher changes: the POSIX and Windows launcher texts are pinned by digest, so an existing installation's tracked launchers (generated by `init`) keep working and only the command `integrate` writes into the untracked settings changes. `fast.claude.LAUNCHER` stays the ownership marker of both forms; neither command is a substring of the other, so neither reads as an edited copy of the other.
2. **Migration and removal.** A re-run over an install made on Windows before this change replaces each owned POSIX group with exactly one `.cmd` group (the earlier groups are the record's own entries, stripped as unchanged), the deny rules move to the Windows set, a third run changes nothing, and `--remove` restores the settings file byte for byte (or deletes a file and `.claude` directory that did not exist before). Tested on every OS through the platform flag `fast.claude.WINDOWS`.
3. **Deny rules on Windows** add, to every POSIX spelling, the `.cmd` launcher and the runtime's `Scripts\python.exe` in each form a command typed in Git Bash can take: `recalith.cmd`; `.recalith/bin/recalith.cmd`, `./…`, `.recalith\bin\recalith.cmd`, `.\…`; the absolute path in forward-slash, native and MSYS (`/c/…`) form; the runtime interpreter relative, backslashed and absolute. Coverage stays `complete: false` with the same four gaps (decision 0019 item 6). The host probe confirmed it (item 7 below).
4. **Capture certification of 2.1.309** (item 3). Its fixtures are `tests/fixtures/hosts/claude/2.1.309/` (the first native-Windows capture); it joins `claude_capture.CERTIFIED_VERSIONS`. The transcript parser keeps its `@2.1.301` name. Tests: `test_reviewed_2_1_309_fixtures_map_like_2_1_306`, `test_reviewed_2_1_309_transcripts_parse_like_2_1_306`, `test_reviewed_2_1_309_fixtures_are_sanitized`.
5. **Sanitization** (tools). One implementation, `probe_common.path_forms`, gives every spelling of a Windows drive path a payload or report can carry (native, forward-slash, JSON-escaped once and twice, MSYS), matched case-insensitively; POSIX paths stay literal and case-sensitive, so POSIX captures and reports are unchanged. It serves both the fixture placeholders and the probe-report `Sanitizer`. The capture adds a Windows `<host-tmp>` rule derived from the child environment as node derives it, and its leak check now requires the written fixtures to be a fixed point of the sanitizer and rejects the login name as a path component. Reports are written with LF on every OS.
6. **The harness on Windows** (tools). Directory junctions instead of symlinks (no privilege); `TerminateProcess` instead of `SIGKILL`; the deny probe's every-form loop and gap commands through `recalith.cmd` (the third gap a quoted launcher path, since bash cannot run a `.cmd` as a script); the private-path probe's interpreter attempt with `python` (`python3` in Git Bash is the Microsoft Store alias); separator-agnostic transcript locators; short stable fixture names (`f01\ws`, homes `h\h1`) and a short harness prefix (`rl-ep-`), bringing the longest transcript path of a live run to about 175 characters (about 220 for a subagent transcript); the worker's PID read until its status record parses (a reader meeting the worker's atomic replace gets a sharing violation, which had made one recovery leg skip its kill). Host termination is a process-tree kill (`taskkill /T /F`); the pty hangup case is POSIX and reports `not_run` on Windows, never a pass. POSIX behavior is unchanged (the POSIX deny commands are pinned exactly).
7. **Host probe result.** `tests/platform/test_claude_smoke.py` now runs on any host with a capture-certified Claude Code, Windows included; on this laptop it ran the complete engine-mode request-capture certification against 2.1.309 (8 passed in 240 s; details in the checkpoint): capture, delivery and compaction restoration through the installed hooks; all four delivery paths request-visible (3/3 positives, 3/3 clean negatives); every covered deny spelling, Windows forms included, denied by the host, and the gap spellings refused by the guard on the actual tool subprocess; the private-path probe; hook failures never denying a tool; the notice reaching the user and not the model; a request-capture-only host record. Request capture certifies nothing.
8. **Worker independence on Windows stays reported, not fixed.** The survival test requires survival and honest reporting (`detached` exactly when the worker proved it left every job), not `detached`. The fix (starting the worker on the base interpreter instead of the venv redirector, outside its job) changes the fast path's worker start and needs its own platform tests; it is an owner decision, not part of this slice. Until then `recalith status` on native Windows reports `recovery` `degraded` (`worker_independence_degraded`) while a hook-started worker runs, even with B1 certified. The evaluation harness does not read readiness.
9. **Thinking blocks in Messages replies** (Task 7 adapter; owner-approved). Current models with adaptive thinking on by default (it cannot be disabled by omission on some) may put a `thinking` or `redacted_thinking` block before the text. The Messages unwrap ignores those blocks (never parsed as the body; no tool, no state) and still requires exactly one text block besides them; tool blocks and `tool_use`/`pause_turn` stop reasons still disable the route; `max_tokens` still caps thinking plus text and the reported output (thinking included) is charged. The adapter digest changes, so a route certified before would report `adapter_changed`; none was. The request body is unchanged (no `thinking` field is sent).
10a. **The live judge in engine mode** (found by the owner's first live delivery run: prompt healthy; session start, pre-action and compaction degraded). The engine harness judged its live trials with the stub protocol's rules, which it had never run live with: (a) the pre-action trial's own fixture command (`ls /nonexistent-recalith-fixture-dir`) was not the stub's (`echo recalith-fixed-output`), so every pre-action trial was `unexpected_tool_use` although all three positives echoed their nonce and all three negatives answered `CANARY NONE`; (b) the session-start and compaction negatives are the same packet shape with the nonce withheld (decision 0019 item 8), so they inject by design and the stub's "a negative injects nothing" rule marked each invalid (`negative_control_injected`) although none carried the nonce and each answered `CANARY NONE`; (c) the open intent question that carries the nonce contradicted itself ("the canary value is X" against "no canary value is recorded"), and the model, told to report a supplied value and not to guess, answered `CANARY NONE` in five of six positives although the nonce was in every transcript. Now an engine trial names its fixture command and whether its negatives inject; such a negative still fails on the nonce anywhere in its transcript or a fabricated value; positives still need the exact echo, three of three; and the two conflicting declarations differ in the option (A or B) while both name the value, so the question stays a real conflict (decision 0013) and the value is unambiguous (negatives name a withheld canary). The stub protocol is unchanged. Request capture on 2.1.309 after the change: all four paths request-visible again.
10b. **The owner's live runs found four more harness defects** (each fixed with tests first): the host-marked parent's decoy `ANTHROPIC_API_KEY` replaced the operator's key (decoys now cover every credential except the selected keys); the runtime check never read the recorded route (`--project`); the evaluation preflight read an invented host-record shape (it now validates the `HostCertification` contract); and the probes wrote model identifiers into the tracked report (the sanitizers now name models by role, the private route keeps the pinned identifier, and `tools/sanitize_report.py` re-applies the rule to earlier evidence). After the fixes the curator route and all four delivery paths certified live on 2.1.309 and the pilot's health reported `ready` (BUILD_PROGRESS, B1 live checkpoint).
10. **The §7 hook gate through the installed command.** `tools/measure_release_latency.py --installed-launcher` runs the warm, cold-missing and stale populations through the exact command `integrate` installs, as the host runs it (Git Bash `-c` → cmd.exe → `.cmd` → the provisioned runtime on Windows; `sh -c` on POSIX); fault and first-launch populations stay direct and are labeled. The gate is unchanged. Results: see the checkpoint.

## Limits (stated, not hidden)

- **Request capture only.** Live delivery and the live provider route are B1; nothing here is a certification.
- **An installation integrated on Windows before this change** keeps its non-functional POSIX hooks until `integrate claude` re-runs, and health reports those hooks `intact`; no such installation exists outside tests (the pilot was not integrated yet).
- **Console close** (a Windows terminal window closing) is not reproducible headless and is not observed.
- **Long paths.** On a Windows without long-path support, deep trial or temporary directories still fail by length (the two evaluation-harness tests above at a 41-character base, and the real-host smoke module under the suite's default temporary layout: a 261-character host transcript); the live gate's output directory must be short (`C:\Code\rl-gate`: about 211 characters for a transcript, 245 for a subagent transcript). Claude Code itself writes such paths; Python opens nothing past 259 characters there, so the worker cannot read a registered transcript of a deeply nested project either (a coverage gap, not a wrong record). Opening through the `\\?\` prefix would lift that; not done here.
- **Concurrent hooks on Windows.** Under a burst of simultaneous hooks a hook's never-waiting read snapshot fails closed with `store_snapshot_unavailable` more often than on Linux (8–12 % of the measured four-hook fault population here, 55 % on CI; `test_concurrent_hooks_preserve_budget` fails 2–3 times in 10 on this laptop, also on the base commit, because its reason assertion does not admit that outcome). Pre-existing; owner decision.
- **macOS** host execution is still unobserved.

## Consequences

Native Windows can capture, deliver and be probed with the shipped harnesses; the B1 operator commands can run there from an ordinary PowerShell. A47, A53, A58, A61, A65 and A73 gain native-Windows request-capture evidence (still `in_progress`; no live variant ran). Decision 0019 item 3's Windows limitation is superseded by items 1–3 and 7 here.
