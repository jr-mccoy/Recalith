# Decision 0018: Profile-aware health, readiness and independent operations (preview)

Status: accepted (Task 17, preview slice) · Date: 2026-10-20 · Host observed: Claude Code 2.1.301 fixtures (capture); installed CLI 2.1.304; no live route (B1)

## Context

Task 17's preview slice is "health, persistent project startup/restart, profile-aware readiness" (IMPLEMENTATION_PLAN Task 17 and its profile table; SYSTEM_SPEC §1.2, §6.1, §10, §10.1, §13, §15; DATA_CONTRACTS §11–§12; ACCEPTANCE_TESTS §2.1 for A02, A03, A40, A45 and A47, plus A29, A46, A49, A65). The documents fix the rules: `health(ctx) -> HealthReport` over the resolved installation only; `autonomous_ready` only when capture, inference, admission, the required session-start and prompt delivery paths, the operator-command guard and recovery/forgetting are healthy for the configured host/provider and profile; optional pre-action/compaction paths reported, never required; deferred features listed unavailable with their reason; capture-only fallback is degraded, not autonomous; pinned/unpinned bytes, live owners, free disk and deferred compaction; exhausted pools, hours to exhaustion and backlog age; source conflicts (one health entry per distinct conflicting digest); private-path coverage that is never claimed as OS isolation; a newer or older schema is never written; startup never migrates silently. They leave open where a host's delivery certification lives per installation, what exactly makes each capability degraded rather than unavailable, how health reports a store this engine cannot read, which parts of startup and upgrade the preview builds, and what `status` exits with. Where a rule was ambiguous the stricter reading was taken.

## Decisions

1. **Preview/full split.** Preview builds: `operations/health.py` (`health`), `operations/autostart.py` (startup *reporting*), the service `health`/`status`/`doctor` and the CLI `status`/`doctor` exit codes. Full-only and not built: engine/schema upgrade (`operations/upgrade.py` is not created; `recalith upgrade`, with or without `--release-profile`, passes the guard and answers 4), side-by-side runtimes, the preview-to-full transition and its rollback, per-project OS startup entries (`integrate --autostart`; reported `unavailable`/`deferred_full_release`), chain diagnostics (`doctor --full-integrity` answers 4; `revision_chain` unavailable). Preview's startup route is the registered hook start of decision 0006: the next project activity starts the pinned worker, so a rebooted installation resumes on its next hook. The plan-named upgrade tests exist as explicit pending skips (`tests/integration/test_upgrade.py`), never passes.
2. **Read-only, one installation.** Health uses read-only SQLite (`mode=ro`, `query_only`; on an idle WAL store SQLite itself may create an empty `-wal` and the `-shm` index, the bookkeeping SYSTEM_SPEC §5.1.1 permits for read snapshots, never a WAL frame or a database byte), file reads and lock probes that never create a file (`autostart.lock_held`: an absent lock file means no holder; an existing one is probed with a non-blocking lock that changes neither bytes nor timestamps). It writes no row, creates no file, launches nothing (no provider `--version`, no host probe: those are the guarded `doctor --probe-*` forms, Task 13), and is not on the hook path; the session-start warning of SYSTEM_SPEC §14 is delivery work (Task 13). No registry, no daemon, no other project is read.
3. **The host record (`.recalith/host.json`, `HostCertification`).** Delivery certification is per installation and per exact host version, like the provider route (decision 0009). Health reads `{certification_schema: 1, installation_id, host_id: claude_code, host_version, mode: live|request_capture, certified_at, report_digest, delivery: {session_start|prompt|pre_action|compact_restore: certified|failed|unavailable}, command_rules: installed|unavailable, private_paths: probed_supported|probed_limited|probed_unsupported|not_run}` (strict, at most 16 KiB, every path present). Task 13's certification produces it; nothing in this build writes it. A record of another installation or a malformed one is `host_certification_invalid`; a `request_capture` record never makes a path healthy.
4. **Capabilities (all reasons are registered codes).**
   - `capture`: the hook manifest judged as the hook judges it (`host_not_integrated`, `hook_context_invalid`, `hook_context_relocated` → unavailable); an unknown or uncertified host version captures in conservative mode (`host_version_unknown`/`host_version_uncertified` → degraded, A47); a store this engine cannot serve is degraded with its schema reason (`schema_migration_required`, `store_schema_newer` or `store_unreadable`: hooks still spool). Capture gaps, quarantined segments and unresolved conflicts are listed (coverage and `coverage_gaps`), not state changes: they are past losses, and the capability is working.
   - `start_delivery`, `prompt_delivery` (required), `pre_action_delivery`, `compact_delivery` (optional): healthy only when the manifest installs the path, the host version is one the hook certifies for delivery, the host record is live, for this installation and this exact version, and certifies the path; else unavailable with every applicable reason (`delivery_not_certified`, `delivery_path_not_installed`, `delivery_path_failed`, `delivery_path_unavailable`, `delivery_request_capture_only`, `host_version_changed`, `host_version_uncertified`, `host_certification_invalid`, …); degraded while privacy maintenance pauses delivery (`maintenance_in_progress`).
   - `inference`: the running worker's own report of its route when its status is fresh (its environment, its isolation recheck), else `route_status` over `provider.json` without observing the executable, against the caller's environment. A missing or uncertified route is unavailable with the route's reasons (`provider_not_configured`, `request_capture_only`, `route_uncertified`, `selected_auth_missing`, …); nothing on PATH is ever a route. An exhausted ordinary pool is degraded (`ordinary_budget_exhausted`); a pending recheck is `isolation_recheck_pending`.
   - `admission`: unavailable when the store cannot be served; degraded when reviews cannot run (`review_provider_unavailable`) or the protected and ordinary pools together cannot carry a review (`protected_budget_exhausted`).
   - `recovery`: the store schema; the `engine.lock` pin versus the running engine (`engine_pin_mismatch`, `engine_pin_unreadable`); OS locking; the registered hook start (`worker_autostart_not_registered`, `hook_context_relocated`); a running worker's independence (`worker_independence_degraded` unless it reports `detached`), stale heartbeat (300 s), errors; a journaled restore (`restore_recovery_pending`); interrupted backups (`backup_recovery_pending`); the latest ledger copy behind the store's epoch (`ledger_copy_stale`); ready segments older than 10 minutes (`ingestion_delayed`); with `doctor`, `PRAGMA quick_check` (`store_integrity_check_failed`). A stopped worker with the hook start registered is healthy: it resumes on the next activity. No verified backup is a coverage gap (`no_verified_backup`), not a degradation.
   - `forget`: unavailable when the store cannot be served; degraded for an unfinished operation or journaled restore (`privacy_maintenance_pending`), owed scratch (`scratch_cleanup_pending`), a completed forget whose post-forget backup failed and no verified backup was made since (`backup_unavailable_after_forget`), and a marker with nothing pending and no privacy lock held (`maintenance_marker_stale`; the worker's next poll drops it).
   - `operator_guard`: the CLI marker guard (registered host, worker and curator markers) is active in this build and exercised by A73; the guard is healthy only when the host record says the command deny rules are installed (`command_deny_rules_not_installed`) and the private-path probe ran (`private_path_probe_not_run`). A probe result of limited or unsupported protection does not gate readiness; it is reported (`private_path_protection_limited`), with `installed_rules: unavailable_in_preview` and `os_level_isolation: false` always: the guard's scope is same-user friction.
   - Deferred: all 16 full-release capabilities are `unavailable` with `deferred_full_release` (`revision_chain` adds `revision_chain_unavailable_in_preview`), in the preview profile (`not_built_in_this_engine` would apply to a full-profile store, which this build cannot create).
5. **Readiness.** `autonomous_ready` is exactly "every required capability healthy" (unchanged contract validator). `readiness` is `ready` then, `unavailable` when the store's schema cannot be served (`migration_required`, `newer_unsupported`, `unreadable`), else `degraded`. A missing provider (B1) is therefore `degraded`, never ready; a preview with both optional paths unavailable can be ready; a missing or failed prompt path is never ready.
6. **`HealthReport` shape.** Added: `readiness`, `checked_at`, `installation` (`InstallationState`: project and installation IDs, running and pinned engine, store and supported schema, `schema_state`, store revision, tombstone epoch), `source_conflicts` (≤256 content-free `ConflictEntry`: conflict, original event, adapter, payload digest, first seen) with `source_conflict_count`, and `privacy_maintenance` (`PrivacyMaintenance`: unfinished operations with phase and status, `scratch_cleanup_pending`, `backup_unavailable_after_forget` operation IDs, `restore_journaled`, `maintenance_marker` `absent|active|stale`, `delivery_paused`, the forgetting `limits`). `retention_summary` is null only when the store cannot be served (then `retention_summary_unmeasured`); a servable store's retention is always measured (the live pin closure, recomputed per call). `budget_summary` adds `exhausted_pools`, `reviews_blocked` and `hours_to_exhaustion` at today's average rate. Capability `coverage` carries the details (manifest, host version, spool backlog and gaps; route source and certified version; startup, worker, journals, ledger, backups, store integrity; guard, deny rules and private-path state). Reason codes from route reasons are normalized to the registered shape.
7. **Unsupported schemas (A40 preview).** Unchanged refusal, now visible: a store at another schema opens only its metadata read-only; health reports `migration_required` (older) or `newer_unsupported`; every store-dependent capability is unavailable or degraded with the schema reason; the worker exits without touching it; guarded writes fail `invalid_schema` (exit 2); a backup at another schema is rejected by `restore` (exit 2) with the live store byte-for-byte unchanged. Nothing migrates; migration is the full-only upgrade. A store at the engine's schema whose pages are malformed where health reads them is reported `unreadable` (`store_unreadable`, readiness `unavailable`) instead of failing `status` with an unexpected storage error; `doctor`'s `quick_check` finds damage elsewhere (`store_integrity_check_failed`).
8. **Copies and moves never start or adopt a worker (A03 preview).** Already enforced by the hook manifest's root identity (decision 0003/0006): a copied or moved checkout's hook refuses with `installation_relocated` before capture or start, in the copy and the original alike; `resolve_installation` refuses a copy and a move awaits an operator rebind. After a rebind the stale manifest keeps the hook off until the integration is re-run (Task 13); health says so (`hook_context_relocated`). `autostart` reports only, and the worker status record counts only when it names this installation.
9. **A capture gap is recorded even when the spool's `ready` directory is the failure.** Writing the health test for A07 found that `spool.record_gap` re-created *every* spool directory first, so a broken `ready` directory (the very failure being recorded) raised and the gap was silently lost. `SpoolDirs.ensure(*only)` now creates only the directories asked for, and `record_gap` ensures only the gap directory (stdlib, the hook import audit unchanged).
10. **CLI.** `status --json` prints identity and epochs, the last retention sweep and the full `HealthReport` under `health` with `autonomous_ready` and `readiness`; `doctor` adds `checks` (`store_quick_check`, `revision_chain`, `private_path_rules`, `command_deny_rules`). Both exit 0 only when ready and 8 (`capability_degraded`) otherwise, with `degraded` the reasons of every required capability that is not healthy (at most 32). A relocated checkout still answers 4 (`installation_relocated`) before any health; a foreign store 2/5 as before. `health_composition_unavailable` is retired.

## Consequences

Wired now: the report through the service and the CLI; the read-only startup report; the A02 preview fixtures (a genuine schema-9 store and backup from the migration files, an older engine pin) and A03 copy/move refusals through the real hook process. No persisted step was added (health and the startup report are read-only), so no new kill/restart family applies; the recovery steps health reports are the Task 15/16 matrices'. Task 13 produces `host.json` (live nonce certification per path, deny rules, the private-path probe), re-runs integration after a rebind and certifies worker survival on the real host. Full release: upgrade/transition/rollback (A02/A40 full), OS startup entries, chain diagnostics (A65 full), session worker and IPC wake (A45 full). No certification follows from this work: B1 still blocks every live check, and health reports it as `provider_not_configured`/`request_capture_only`.
