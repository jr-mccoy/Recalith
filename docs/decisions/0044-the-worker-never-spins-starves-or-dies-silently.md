# Decision 0044: The worker never spins, starves work or dies silently; retention, forgetting and review finish what they start

Status: accepted (Tasks 4, 6, 8, 9, 15 and 16, preview) · Date: 2026-11-08 · Engine: `0.1.0.dev12` · Observed: the pre-publication audit of `0.1.0.dev10` ([report](../audits/2026-11-06-memory-system-audit.md), Phase 1 of [the fix plan](../audits/2026-11-06-fix-plan.md))

## Context

The audit reproduced, against real installations with the fake provider and a virtual clock, a set of defects in the worker and in the maintenance it runs. None breaks a gate on a short live run; each would bite a real user over days.

- **CTL-1 (high): a slow job was relaunched without end.** A model lease lasted the call timeout plus 60 s (180 s), and nothing renewed it across evidence-expansion rounds. A job whose two or three calls took longer was fenced out of its own result, stayed `leased`, was leased again from round 0 and relaunched, charging two calls per cycle and never failing.
- **CTL-2 (high): a near-fit job starved everything behind it.** The pre-lease check covered only the smallest possible reservation. A job whose exact estimate did not fit was leased, prepared and parked in `waiting_budget` with its due time unchanged, so it was first again a second later. A protected `revalidate` with its own reserve was never leased.
- **CTL-3 (medium): the backoff ladder stalled.** A model job's attempt counted only after a reservation, so a prepare or apply failure retried every 60 s forever and never reached `failed`.
- **CTL-4 (medium): a bug killed the worker invisibly.** A poll step raising anything but four exception types escaped the worker; the status file still said `idle`, and every hook restarted it into the same bug.
- **CTL-5 (medium): unjudged candidates were frozen.** A candidate the reviewer omitted, or rejected with `review_capacity`, was never reviewed again, although SYSTEM_SPEC §7.2 promises bounded retries.
- **STO-1 (medium): retention livelocked.** The sweep took its 4,096 oldest age-eligible payloads before excluding pins. Once all of them were pinned, nothing expired again, and the truncated sweep re-ran its two pin closures every poll.
- **STO-2 (medium): a backup kept forgotten text.** `backup.holds()` looked only at payloads, capsules and revision bodies, while the live purge also scrubs operation inputs, proposal bodies, source-conflict bodies and delivered items. A backup holding the forgotten narrative only there was not treated as affected.
- **CAP-5 (medium): an abandoned red attempt never became an episode.** A range with an unresolved failing test was kept open until the same test passed; with no fix ever coming, it was never condensed or extracted.
- **CAP-4 (medium): lineage ignored four certified hosts.** The artifact-snapshot rule applied to Claude Code 2.1.301 only, so on 2.1.305 to 2.1.310 two reads of one unchanged file from different working directories counted as two roots.
- **FP-2 (medium): a live session could lose its lock.** Acquiring the session lock never refreshed its file time, and the 24-hour prune deleted lock files by their own time. A session alive a day lost its lock file, and the next hook locked a new inode while another hook still held the old one.
- **PROV-2, PROV-3 (medium): the CLI route misread replies.** Its stream-json envelope was split with `str.splitlines()`, which cuts at U+2028/U+2029/U+0085 that Node leaves raw; and every error result became `envelope_invalid` or a bare `provider_failed`, so a revoked key never withdrew the route.
- **Small (low):** a read-only view accepted `PRAGMA x = y`; the stop file and the backup journal directory took the umask; the main thread could close the model lane's connection under an in-flight call; a request told the model a 120 s timeout whatever was configured; episode refs were paired with tasks by position; "paused within 24 hours" read `updated_at`, which any narrative patch refreshes; a source tail whose every event was refused was re-read every poll.

## Decisions

1. **A model lease covers the whole call** (`jobs.lease_seconds`): every allowed round times the timeout, plus the margin (420 s by default). The lane renews it before each expansion round. A lease that still runs out under its own worker is a failed attempt on the ladder (`jobs.fail_expired`, `lease_expired`), never a free re-lease from round 0; a newer lease taken by another owner is left alone. The deterministic lane does the same.
2. **A budget wait has a due time** (`jobs.wait_budget`): the earlier of ten minutes and the next UTC day. Until then the job is not a lease candidate, so it is prepared at most once per window and later bands, protected revalidation included, are leased. Decision 0006 item 10 ("a job that cannot fit is never leased") held only for the invocation dimension; this makes it true in effect for all of them.
3. **Every lease is an attempt**, counted when it is taken, for model jobs as for deterministic ones. A lease that turns out not to be one gives it back: a budget wait, an unavailable provider, and a `PrepareDeferred` (a busy task's narrative, `task_active`), which is now a release with a due time rather than a failure. The ladder is 1, 5 and 30 minutes, then `failed`, for every failure.
4. **A poll step's error is contained and visible.** After privacy recovery (which ends the poll if it fails), every step runs on its own: an exception of any type is recorded as `poll_error:<step>:<type>`, the remaining steps still run, and the status shows the first error. A fatal error writes `state: crashed` with `worker_crashed:<type>` before the worker exits (exit 5, the type only); health reports `worker_crashed` under recovery until a hook starts a new worker.
5. **Unjudged candidates are reviewed again, bounded.** A candidate whose verdict was missing, or a sole `review_capacity` reject, goes alone into a new batch (so it has the whole response budget), keeping the original provenance, at most three times per claim; then it is recorded `deferred` with `review_retry_limit` and stays a candidate. A head written by anything but that review's own verdict is left to its own review. `revise` is unchanged: its objections stand until a changed proposition is resubmitted (decision 0011).
6. **The retention sweep pages past pins.** Candidates are taken in commit order with pins excluded while paging, at most 16 pages of 4,096 rows per sweep; a truncated sweep records where it stopped (`resume_after` in its report, no schema change) and the next continues there, wrapping to the start. Every truncated sweep makes progress or wraps.
7. **A backup holds what the purge scrubs.** `backup.holds()` also checks operation inputs and changes, proposal bodies (including those found through the operations that wrote closure records and the jobs that read them), source-conflict bodies and delivered items, with the purge's own ID pattern and content-free operation list. A table an older snapshot lacks is skipped.
8. **An unresolved range is recorded when its task goes quiet.** A session end still keeps it open, because a resumed session may bring the fix into the same episode (an episode may span sessions; the cross-session working-memory test depends on it). The idle pause (24 hours by default) now records it as an `open` episode with its failure in `unresolved`, and extraction is scheduled for open episodes as for settled ones (also covering the 64-step flush). Narrative stays settled-only. A later fix lands in the next episode, which names the open one as related.
9. **Lineage follows the capture-certified versions.** `core.lineage` lists the five certified versions; a test keeps the list equal to `fast.claude_capture.CERTIFIED_VERSIONS` (the core layer imports no host adapter). Roots registered before this engine keep their tokens; only new reads use the snapshot rule, so an old and a new read of one file may still count as two classes.
10. **A session lock is held by exactly one hook.** `acquire` checks, after locking, that the path still names the file it locked (reopening otherwise) and refreshes the file's time. The prune removes a session's files only when every one is idle and only while it holds that session's lock; on POSIX it unlinks the lock while holding it, on Windows after releasing it (Windows deletes no file another handle holds open).
11. **The CLI envelope is split on `\n` only**, in the adapter and in the probe. A result event that is not a success is classified, content-free, from the host's error text: `provider_auth_rejected` (which withdraws the route, as a 401/403 does on the API path), `provider_request_rejected` for credit, `provider_rate_limited`, `provider_overloaded`, else `provider_failed`; a nonzero exit reports the same code when its output names one.
12. **The small ones.** Read views accept only named check and listing pragmas and argument-free value reads. The stop file is 0600; the backup journal, forget marker and restore journal directories are 0700. A pending restore waits for an in-flight model call instead of closing its connection. Requests name the configured timeout. Episode refs must match the planned tasks one for one. Continuity judges a paused task by the start of its current pause. A source tail whose every event was refused (`policy_refused`/`invalid_schema`) moves the cursor past it and records a `source_events_refused` gap; an I/O failure keeps the cursor.
13. **Engine `0.1.0.dev12`.** The CLI adapter changed, so a certified Claude CLI route on an earlier engine reports `adapter_changed` until recertified. The release checklist's smoke gate stays blocked (decision 0043).

## Rejected

- **Close an unresolved range at session end** (the audit's plan item 1.8). It severs a failure from the fix a resumed session brings, which SYSTEM_SPEC §3.3 forbids for the boundaries it names and the working-memory tests protect. The idle pause is the point after which no resumed fix can be expected.
- **A sweep cursor column in `retention_state`.** The sweep's JSON report already persists per sweep; a resume point there needs no schema change and no migration.
- **Retry `revise` automatically.** A revise means the wording must change; re-reviewing the same proposition would only repeat the objection. Resubmission belongs with extraction.
- **Kill a healthy in-flight call to let a restore finish sooner.** SYSTEM_SPEC §6.3: preemption chooses the next job, it never kills a healthy call.

## Tests

- `tests/integration/test_worker.py`: three 100 s rounds complete on one lease with three charged calls; a call outliving the whole lease fails onto the ladder; a near-fit extraction is prepared once per window while a protected revalidation completes; the due time never passes the next UTC day; a persistent prepare failure reaches `failed` after 1, 5 and 30 minutes with nothing reserved; a busy task's narrative is deferred without counting attempts; a planner bug leaves the worker running with the error recorded and retention still run, and a fatal error leaves `crashed`, which `worker_report` and health report.
- `tests/integration/test_claim_admission.py`: a capacity-limited candidate is retried alone at its latest revision while judged and refused ones are not; an unjudged candidate is retried exactly three times, then `review_retry_limit`.
- `tests/integration/test_retention.py`: with a one-row window every truncated sweep expires exactly one unpinned payload until none is left; an all-pinned store pages through and wraps.
- `tests/integration/test_forgetting.py`: a backup with no payloads or bodies but forgotten text in bookkeeping is affected; once that bookkeeping is scrubbed it is not (fails on `0.1.0.dev11`).
- `tests/integration/test_episodes.py`: an unresolved range survives a session end, becomes an open episode at the idle pause and is extracted.
- `tests/unit/test_lineage.py`: the rules cover exactly the certified versions, and two reads of one file from different directories share a class on each.
- `tests/platform/test_session_scratch.py`: a lock in use is never pruned; an idle session is pruned whole, but not while its lock is held; a waiter whose locked inode was unlinked reopens the live file.
- `tests/unit/test_provider_contract.py`: a reply quoting each separator unwraps intact; six host error texts name their codes, the auth ones withdrawing the route, through `unwrap` and through a nonzero exit.
- `tests/integration/test_audit_small_fixes.py`: read-view pragma writes refused and reads allowed; the stop file 0600; continuity by pause start; the request's timeout; the journal directory 0700 (fails on `0.1.0.dev11`).
- The existing `test_review_capacity_is_not_a_refutation_and_cannot_loop` now expects the one bounded retry; its other assertions are unchanged.

## Limits

- **The refused-tail cursor (decision 12) has no dedicated test.** Reaching it needs an event that normalization accepts and the capture re-check refuses, which no current adapter produces; the change is a few lines on that path.
- **A pending restore that waits on a model call** (decision 12) is exercised only through the existing restore tests; a threaded test of the wait itself is not written.
- **The CLI error classification reads host error text.** It is a pattern match over the host's own message, never stored; an unfamiliar wording falls back to `provider_failed`.
- **Open episodes are extracted;** whether the curator words an unresolved attempt well is a live-quality question for the next gate.

## Consequences

The owner provisions a fresh pilot from the `0.1.0.dev12` wheel (or a later Phase engine) before any live run; Phase 2's retrieval changes follow before the gate is re-run (fix plan Phase 5).
